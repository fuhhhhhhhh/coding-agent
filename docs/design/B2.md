# B2：安全读 Action、执行边界与有条件交付

状态：安全交付回补在 Linux Local/Rootless Docker/官方 DeepSeek Flash 范围通过受限验收；B2 整体仍有未完成项。下文首节保留首个增量的历史契约，最新设计和结果见文末。

## 目标

解决两个直接影响日常使用的问题：普通仓库检查不应因为调用了 Shell 就反复审批；交互式 CLI 应该能在输入 `/` 时给出可发现的命令入口。实现沿现有权限执行器和 `codepilot` 入口扩展，不创建第二条 Shell/Git 执行链。

## 内部契约

`Action` 由权限层从 `ToolSpec`、`ToolCall` 和实际后端生成，包含工具效果、调用 ID、参数摘要与 SHA-256、cwd、后端类型/实例、资源和最终指纹。审批请求同时保存 Action 和参数快照；`PermissionedExecutor` 在授权返回后重新生成指纹，变化则拒绝执行。Shell 命令原文不进入审批摘要，避免把潜在秘密回显到终端。

直接工作区的每个正式 run 在私有会话目录保存 `workspace-baseline.json`，结束时比较当前清单并把变更摘要写入 SessionEvent。清单只含相对路径、文件模式和内容哈希，不保存正文；基线缺失或损坏时记录 `workspace_manifest_unavailable`，不会把归属误判为空，也不会自动回滚。

`PermissionPolicy.safe_process_reads` 是策略能力开关。开启后，`PermissionEngine` 先调用 `is_safe_process_read(ToolCall)`；只有返回真才以 `allow/safe_process_read` 记录审计，否则继续走原来的 `allow/ask/deny` 规则。`read-only` 不开启该能力。

安全识别先拒绝 Shell 元字符、未闭合引号和带配置注入形态的参数，再允许固定查询集合：`pwd`、有限 `ls`、`git status`、`git log`、`git branch` 查询、`git rev-parse` 查询和 `git ls-files`。多个查询只有在全部由 `&&` 连接、且每一段都独立通过白名单时才自动放行；混入其他组合符号或副作用命令就回到审批。这不是通用 Shell 安全分析，也不声称能保护宿主。

交互入口的 `_read_interactive_task` 在真实 TTY 使用 cbreak 逐字符读取，输入第一个 `/` 时显示命令提示；stdin/stdout 非 TTY 继续调用 `input()`，保持管道与测试协议稳定。`_handle_slash_command` 只处理外壳命令，不把它们发送给 Provider。

交互循环还在 Provider 调用前识别 `codepilot resume/run/sessions`。这些是进程外 CLI 命令，不是任务内容；检测到后提示用户退出当前提示符并在 Shell 执行，避免模型猜测命令含义。

## 正常轨迹

用户启动 `codepilot` → 欢迎卡片 → 输入 `/` 查看命令 → `/status` 查看会话/目录/模型/后端 → 输入任务 → 模型请求 Shell `git status --short` → Action 白名单自动放行 → Shell 结果进入原有 Trace、持久会话和 Runtime → 输入 `/sessions` 查看会话索引。

## 重要失败场景

1. `pwd && ls -la` 的每一段都是严格查询，可以自动放行；`pwd && git commit ...` 混入副作用，必须审批，拒绝后不启动进程。
2. `printf unsafe`、`git commit`、`git fetch` 以及包含重定向/命令替换的调用不在白名单，不能因为出现“只读词”而自动放行。
3. TTY 输入过程中 Ctrl-C、Ctrl-D 或异常必须恢复终端属性；非 TTY 不输出 ANSI 或菜单控制序列。
4. 未知 `/command` 只产生可恢复提示，不创建任务、Trace 或 Provider 请求。
5. 基线清单损坏或工作区含特殊文件时，任务事实仍可保留但变更归属进入未知，不能提供盲目撤销。

## 取舍和后续

当前白名单只降低明确查询的摩擦，不能替代完整 B2 Action：后续仍需把 cwd、后端、工作区身份、网络/秘密能力、审批有效期和策略版本纳入标准化 Action，并在执行前复核。TTY 菜单目前是可发现提示，不是完整上下键选择器；避免在没有稳定终端状态模型前引入复杂 TUI。

## 2026-10-19 安全执行与交付收尾实施契约

本轮沿统一产品入口实施：控制器私有逐调用文件修改日志、零模型审查/撤销、审批过期与策略/工作区身份复核、最小子进程环境、Docker 显式隔离使用完整独立 Git 副本。默认仍直写当前目录。日志只为明确的 write_file/edit_file 提供归属，不把任意 Shell 的全部文件变化冒充可安全撤销；Shell、MCP、后台写入仍由全工作区基线补充审查。

修改日志保存调用前意图与正文快照、预期后版本，执行返回后才确认；崩溃留下 intent/unknown，不能自动撤销。审查只显示路径/哈希/状态，正文留在 0700/0600 私有会话目录。撤销先检查整批路径、当前版本和普通权限，任何冲突先拒绝整批；开始后逐文件记录进度，不声称跨文件原子事务。保存失败必须发生在工具副作用前；结束记录失败则进入未知状态。限制单文件 1MiB，单 run 日志正文配额 16MiB，拒绝超限的新编辑。

审批有效期使用单调时钟；批准返回后复核策略摘要、后端身份、根目录设备/inode 与调用参数。Local 仍为可信宿主执行，最小环境只避免意外继承 Provider/代理/SSH 凭据，不承诺隔离宿主文件或网络。Docker 继续 network=none，不实现未经强制代理验证的域名授权。显式硬工作区磁盘配额请求在当前 bind 后端失败关闭，不把扫描和输出配额称为工作区硬配额。

Docker 的 --worktree 改用固定 commit 的完整独立 clone，不挂载源 .git 或凭据；移除 origin，不继承源仓库 hooks/config，不使用共享 objects/hardlinks。交付从固定 base 比较，包含任务自身 commit 产生的变化，仍保留二进制 patch 与新工作树重放，失败保留副本。Local 的显式 worktree 保持既有行为。

### 限容副本的实现与恢复契约

用户通过 `--backend docker --docker-image codepilot-sandbox:0.1.0 --bounded-workspace-bytes 8388608` 显式选择复制式执行。默认 bind 仍直接编辑当前目录，不偷偷变成复制模式。仅支持 Linux Rootless Docker、1—64MiB、4096 字节对齐，任务盘最多占容器内存四分之一，避免归档导入与 Python worker 没有内存。Local、rootful、与 `--worktree`/可执行扩展的组合明确拒绝。

控制器用真实脏文件建立 `bounded-baseline/` 和 `bounded-workspace/`，清单保存源目录设备/inode、逐文件 SHA-256/普通权限、before/after、changed_files、applied_paths。排除 `.git`、`.env*` 和缓存，不承诺识别任意文件中的秘密；模型看到的副本不含源 Git 历史。源 Git 元数据留在原目录，复制模式中可以自己运行原生 `git init`，产生的 Git 元数据不交付到源目录。非 Git 目录也能使用。

容器 `/workspace` 是带 size/nr_inodes 的 tmpfs，内核强制容量；控制器私有副本不是硬限容磁盘。会话另以 `workspace_artifact_bytes`（默认 1GiB）对每个 run 预留 `7*workspace_bytes+64MiB` 的逻辑额度，预留不提前释放，随 sessions delete/prune 回收。它用于防止无限累积正文，不是宿主物理磁盘、目录 inode 或掉电耐久性的保证。

导入/导出使用固定 worker 归档协议，限制归档字节数、条目数、普通文件类型，拒绝绝对路径、穿越、链接和特殊权限。**实测 `docker cp` 不导出 tmpfs 内容**，因此没有使用该路径。每次修改工具/Shell 后保存检查点；最终导出先在自有带 init 的 PID 命名空间中暂停其他写进程，再取归档，随后才能删除容器。导出失败记录 backend_close_failed，保留确切容器身份及上次成功归档，不能把清理失败伪报成 backend_closed。所有权登记在 create 返回后立即完成，登记/启动/握手失败也进入精确清理出口，删除失败保留 ID。

状态：preparing → active → retained/empty；正常 Runtime completed 才尝试 retained → applying → applied，取消/错误只保留产物。completed 是交付资格，不代表测试已经通过。交付前对整批源路径与所有产物核验，再逐文件复核与原子写入/删除，写后保存 applied_paths。与基线不同的源文件使整批拒绝；第二文件写失败则保留 applying 和真实部分进度，跨进程重开不能自动补做。撤销路径 applied → undoing → undone，先要求源仍等于任务交付版本。支持 Shell 产生的二进制文件、新建、删除和普通权限；不承诺重命名身份、ACL/xattr、空目录恢复、跨文件原子事务或恶意同 UID 并发写入的文件系统 CAS。

`codepilot delivery SESSION RUN` / `/delivery RUN` 预览保留产物，`--apply` 显式交付；`changes` 审查、`undo --apply` 有条件撤销。维护复用会话身份、锁、needs_reconciliation 和真实版本核验，不请求模型。未知 applying/undoing 不重放。默认 bind 的撤销仍只认领可确认的文件工具修改；不能借复制模式承诺任意宿主 Shell 的全量撤销。

已知限制：容器 OOM、强制停止、daemon/主机崩溃可能丢失自上次检查点以来的 tmpfs 内容。导出失败保留容器也不是永久耐久存储。限容容器带 workspace_mode 标签，自动过期清理跳过它，resources prune 同样拒绝静默删除并报告 bounded_workspace_requires_export；正常关闭仍在成功导出后精确删除。跨控制器孤儿容器的自动导出恢复未实现，不能声称崩溃后自动重建任务。容量不足时错误可诊断、源目录不自动收到失败任务的产物。任务可以写满 tmpfs 或制造不支持的链接，归档拒绝时保留资源等待人工协调，不自动扩大权限或挂载源目录。

官方依据：[Docker tmpfs](https://docs.docker.com/engine/storage/tmpfs/)、[docker cp 限制](https://docs.docker.com/reference/cli/docker/container/cp/)。本轮实测与失败修复保存在 `docs/evidence/B2-repository-*`。网络仍 none，短期秘密注入尚未实现，不能据这个增量宣布 B2 或成熟发布整体通过。

分页默认扫描上限 16MiB（配置参数最大 64MiB），返回页上限沿原 max_bytes；行窗口最多 2000 行。生产写入日志仍限制单文件 1MiB、单 run 16MiB 编码 JSON；分页能够阅读更大文件，不等于解除编辑/日志配额，超限须明确失败而不是绕开归属。检索默认单文件 1MiB、总扫描 32MiB，可显式提高到 8MiB/128MiB；枚举最多 2MiB NUL 文件名和 20,000 路径、输出约 64KiB，覆盖未完整时标记 truncated。长行输出有片段位置与 shortened_lines 计数，不把 500 字片段伪装完整命中行。

### 目录结构与边界原因

```text
src/codepilot/
  app/                 # 统一装配、会话锁与交付资格；维护命令也在这里
  tools/
    pages.py           # 文本页与版本游标；不是新的模型工具
    read_file.py        # 原读取工具参数与兼容入口
    search.py          # 原生忽略枚举、有界检索和覆盖
    edit_file.py        # 原编辑工具的批次预检查/部分结果
  workspace/
    changes.py         # 工具日志、生产读版本与可确认归属
    bounded.py         # 源目录与私有副本版本、交付/撤销状态
    archive.py         # 容器内固定归档/停止写入协议
    docker.py          # 内核资源约束、进程与容器生命周期
  scheduler/           # 批次整体写资源锁，避免读写调度假装互不影响
  ui/                  # CLI/斜杠入口及交付状态显示
 tests/                # 确定性故障与显式 Rootless 真机测试
 docs/{design,learning,evidence}/ # 契约、阅读轨迹与真实结果分别保留
```

没有另起第二个 Agent Runtime，也没有增加与 Git 子命令一一对应的包装工具。归档协议只在控制器和其自有容器间通信，不作为模型可任意选择宿主路径的工具。

日志预留按每个文件的原内容和目标内容中较大的 base64 编码量加元数据计算，兼顾执行失败时原文件保持不变的后快照；整批仍必须在 16MiB 编码 JSON 上限内。避免把 16 个小文件都按 2MiB 最坏文件计费而误拒。确定性与真实 worker 测试均覆盖最大 16 文件的读取、批次修改、确认和撤销。

## 2026-10-20：受控 HTTPS 与凭据代理（实施契约）

本组连续完成配置→Action/审批→调度→控制器 HTTPS 代理→有界结果→会话/Trace→取消清理及诊断的统一链，不另建 Runner。Docker 仍 network=none；仅新 http_request 工具可以请求用户配置的精确 HTTPS 目的地。此为请求级代理，不是 Shell 透明代理，不冒充已支持联网 Git/pip/SSH。

契约：NetworkConfig 默认关闭，仅用户/显式配置可启用；精确 hostname:443、路径前缀、每 run 请求/响应字节/总字节/租期上限。GET 请求不接收任意 header/body/cookie/代理地址；模型只能选 URL 和秘密引用。秘密配置仅含外部私有文件路径、绑定目的地/路径；Bearer 值在成功 TLS 后才读取，仅用于本次请求，不进容器环境、参数、会话正文或 Trace。Provider 凭据来源不能复用为工具秘密。作用域和配置摘要进入 Action 指纹，调度后沿已有机制复核。

每次请求独立解析 DNS，所有地址须为公开单播地址；连接已核验 IP，TLS SNI/证书仍核验原域名，避免二次 DNS。匿名重定向逐跳重新校验和扣额度；带秘密请求不跟随重定向。没有自动重试。错误不回显远端异常正文/响应头；正文有界完整收集后检查已知秘密原文及常见编码回显，再进入既有 Context/Session 输出链。认证失败不给模型回显响应正文。租期到期、取消、额度耗尽关闭连接，不延长授权。

重要失败：①私网/混合 DNS、IP 字面量、URL 用户信息或重定向越界均不发送目标请求；②秘密文件不私有/被替换/过期、服务端反射秘密均不发布秘密；③超大/压缩/畸形/截断响应不发布完整成功；④审批拒绝、排队过期、DNS/握手/读响应超时和取消不留下活动 socket；⑤控制器崩溃不恢复旧网络请求，旧调用结果未知时沿既有 needs_reconciliation。

验收命令：`.venv/bin/python -m pytest -q`、`.venv/bin/ruff check .`、`.venv/bin/ruff format --check .`、`.venv/bin/mypy`、`uv build --wheel`；随后 `CODEPILOT_DOCKER_LIVE=1 ... pytest` 验证实际断网、代理公开 HTTPS、秘密未进入容器和会话。真实模型冻结官方 DeepSeek Flash 最多 8 请求，仅公开 GET/读文件；不执行外部写入，不使用真实业务秘密。合成秘密仅发往本机受控 TLS fixture；fixture 只替换测试 DNS/信任根，生产没有私网放行开关。四层结果独立记录。

边界：Local 可信宿主 Shell 仍可自行联网，因此启用代理要求 Docker；不允许项目配置扩大此能力。不支持透明依赖安装、Git fetch/push、远程 MCP 网络授权或任意编码秘密检测；这些仍是明确发布缺口，不能以请求级代理替代系统级网络代理。

### 实现落点与状态所有权

- `network/models.py`：不可变 Destination/SecretReference/NetworkConfig；固定 HTTPS:443、规范 ASCII 路径和目录边界，不允许通配符、IP 字面量或编码路径。secret 文件仅存引用，模型参数不接受 header/body。
- `network/broker.py::HttpRequestTool.run/_request`：单 run 共用锁/请求数/解密后 HTTP 字节数/租期；发送前持久 reserve，响应后记录 response_received，异常记录 unknown_or_failed。这不是服务端未执行证明，也不触发重试。每个重定向重新核验/扣额；响应有界收集后才进入上下文。
- `_request` 用 asyncio 原生可取消 TLS，固定已核验数字 IP、原域名 SNI 和证书验证，忽略宿主代理环境。HTTP/1.1 消息边界由 h11 公开 API 处理，不自己写 HTTP 解析器。生产没有跳过证书/允许私网开关；测试 TLS fixture 的 DNS/信任根替换不能当生产公开 DNS 证据。
- `read_secret`：获批连接 TLS 通过后才读取；外部 owner-only 普通文件、O_NOFOLLOW/fstat/读前读后身份核验、单行 Bearer。文件元数据进入审批指纹，排队后仍由原 EXECUTION_GUARD 复核。引用租期只是此次 run 的使用期限，不是向服务端签发/撤销临时令牌；原用户凭据文件不会被删除，Python 不保证擦除内存中的不可变字节。
- `app/service.py::_network_tools`：只给主链 Router 增加一个真实工具，无第二套执行器；主权限/调度/Context/会话/Trace 均复用。子 Runner 的既有只读集合不含网络工具。`operations.fetch` 和 CLI `/fetch`/`fetch` 为同链零模型入口；非 TTY 缺批准时明确拒绝。
- `doctor`、`permissions` 只展示目的地/引用名和本地元数据有效性，不读取值或测试远端可达。`network_attempt` 事件只存 call/run/状态/额度，不保存 URL、响应头和秘密。响应正文在过滤后按原会话/Context 配额存储，不把未经检查的 HTTP 原文保存为 Artifact。

安全失败优先于便利：认证请求重定向全部拒绝；认证失败不返回服务器正文；压缩、1xx、升级、非 UTF-8 和畸形消息明确不支持。不会接受任意 HTTP POST，也不把 GET 当作服务端无副作用的保证；每次仍属 process 审批。精确目的地授权不等于防止模型把用户资料放在获批 URL 查询中，用户应只授权可信服务，响应仍是可能含提示注入的不可信资料。原文/base64/URL/hex 回显检测不覆盖任意编码、拆分或恶意侧信道。

官方实现依据：[Python 3.11 asyncio streams](https://docs.python.org/3.11/library/asyncio-stream.html)、[ipaddress](https://docs.python.org/3/library/ipaddress.html)、[h11 公开事件/状态 API](https://h11.readthedocs.io/en/stable/api.html)。使用现有传递依赖 h11，但显式加入直接依赖与锁文件，不依赖 SDK 恰好安装它。

最终状态约束：在首次写 socket 前持久保存 request_sending；只有完整 HTTP EndOfMessage 才能清除本次 network_pending。已发送但截断/取消/读超限等未知结果标 unknown，同 run 后续网络请求拒绝，限容副本不自动交付，SessionStore.finish 即使收到配对错误和 Runtime completed 也保持 needs_reconciliation。诊断/JSON/终端显式展示；用户必须在原 `sessions reconcile ... --accept-workspace` 之外再明确加 `--accept-network-unknown`，表示接受远端结论仍未知、不重放旧调用，而不是证明远端未执行。只在 TLS/DNS 之前失败或已完整收到但正文被拒绝时不会制造未知远端阻断。真实 TLS 截断产品测试同时覆盖离线与 Rootless 模式。

### TLS 环境隔离补充

最终复核发现，CLI 便利加载的项目 `.env` 能设置 SSL_CERT_FILE/SSL_CERT_DIR/SSLKEYLOGFILE；请求代理不能采用会读取这些值的默认 TLS 工厂。`system_tls_context` 使用 PROTOCOL_TLS_CLIENT、OpenSSL 编译时系统 CA 路径与显式 load_verify_locations；找不到可信路径即失败关闭，不回落到环境 CA，不开启 TLS 密钥日志。不会修改用户环境或服务器信任库；自定义工作区/用户 CA 覆盖不作为已支持能力。测试合成 CA 与日志路径实际注入环境后仍不能信任该 CA 或创建日志，公开 HTTPS 则用生产上下文重新真实验证。capath 的 CA 按 OpenSSL 需要惰性加载，初始 get_ca_certs 为空不能据此判为缺少系统信任。

依据：[Python SSL 默认工厂的密钥日志环境行为与自定义上下文](https://docs.python.org/3.11/library/ssl.html#ssl.create_default_context)、[编译时信任路径与环境路径的区别](https://docs.python.org/3.11/library/ssl.html#ssl.get_default_verify_paths)。实际最终计数和安装/容器复验见 B2-network-checks.json，不以父提交的旧计数代替新修复验证。
