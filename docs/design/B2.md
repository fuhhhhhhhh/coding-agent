# B2：安全读 Action、执行边界与有条件交付

状态：安全交付回补在 Linux Local/Rootless Docker/官方 DeepSeek Flash 范围通过受限验收；B2 整体仍有未完成项。下文首节保留首个增量的历史契约，最新设计和结果见文末。

## 目标

解决两个直接影响日常使用的问题：普通仓库检查不应因为调用了 Shell 就反复审批；交互式 CLI 应该能在输入 `/` 时给出可发现的命令入口。实现沿现有权限执行器和 `codepilot` 入口扩展，不创建第二条 Shell/Git 执行链。

## 内部契约

`Action` 由权限层从 `ToolSpec`、`ToolCall` 和实际后端生成，包含工具效果、调用 ID、参数摘要与 SHA-256、cwd、后端类型/实例、资源和最终指纹。审批请求同时保存 Action 和参数快照；`PermissionedExecutor` 在授权返回后重新生成指纹，变化则拒绝执行。Shell 命令原文不进入审批摘要，避免把潜在秘密回显到终端。

直接工作区的每个正式 run 在私有会话目录保存 `workspace-baseline.json`，结束时比较当前清单并把变更摘要写入 SessionEvent。清单只含相对路径、文件模式和内容哈希，不保存正文；基线缺失或损坏时记录 `workspace_manifest_unavailable`，不会把归属误判为空，也不会自动回滚。

`PermissionPolicy.safe_process_reads` 是策略能力开关。开启后，`PermissionEngine` 先调用 `is_safe_process_read(ToolCall)`；只有返回真才以 `allow/safe_process_read` 记录审计，否则继续走原来的 `allow/ask/deny` 规则。`read-only` 不开启该能力。

安全识别先拒绝 Shell 元字符、未闭合引号和带配置注入形态的参数，再允许固定查询集合：`pwd`、有限 `ls`、`git status`、`git log`、`git branch` 查询、`git rev-parse` 查询和 `git ls-files`。多个查询只有在全部由 `&&` 连接、且每一段都独立通过白名单时才自动放行；混入其他组合符号或副作用命令就回到审批。这不是通用 Shell 安全分析，也不声称能保护宿主。

交互入口的 `_read_interactive_task` 在真实 TTY 使用 cbreak 逐字符读取，输入第一个 `/` 时显示命令提示；stdin/stdout 非 TTY 继续调用 `input()`，保持管道与测试协议稳定。`_handle_slash_command` 只处理外壳命令，不把它们发送给 Provider。

交互循环还在 Provider 调用前识别 `codepilot resume/run/sessions`。这些是进程外 CLI 命令，不是任务内容；检测到后提示用户退出当前提示符并在 Shell 执行，避免模型猜测命令含义。

## 正常轨迹

用户启动 `codepilot` → 欢迎卡片 → 输入 `/` 查看命令 → `/status` 查看会话/目录/模型/后端 → 输入任务 → 模型请求 Shell `git status --short` → Action 白名单自动放行 → Shell 结果进入原有 Trace、持久会话和 Runtime → 输入 `/sessions` 查看会话索引。

## 重要失败场景

1. `pwd && ls -la` 的每一段都是严格查询，可以自动放行；`pwd && git commit ...` 混入副作用，必须审批，拒绝后不启动进程。
2. `printf unsafe`、`git commit`、`git fetch` 以及包含重定向/命令替换的调用不在白名单，不能因为出现“只读词”而自动放行。
3. TTY 输入过程中 Ctrl-C、Ctrl-D 或异常必须恢复终端属性；非 TTY 不输出 ANSI 或菜单控制序列。
4. 未知 `/command` 只产生可恢复提示，不创建任务、Trace 或 Provider 请求。
5. 基线清单损坏或工作区含特殊文件时，任务事实仍可保留但变更归属进入未知，不能提供盲目撤销。

## 取舍和后续

当前白名单只降低明确查询的摩擦，不能替代完整 B2 Action：后续仍需把 cwd、后端、工作区身份、网络/秘密能力、审批有效期和策略版本纳入标准化 Action，并在执行前复核。TTY 菜单目前是可发现提示，不是完整上下键选择器；避免在没有稳定终端状态模型前引入复杂 TUI。

## 2026-10-19 安全执行与交付收尾实施契约

本轮沿统一产品入口实施：控制器私有逐调用文件修改日志、零模型审查/撤销、审批过期与策略/工作区身份复核、最小子进程环境、Docker 显式隔离使用完整独立 Git 副本。默认仍直写当前目录。日志只为明确的 write_file/edit_file 提供归属，不把任意 Shell 的全部文件变化冒充可安全撤销；Shell、MCP、后台写入仍由全工作区基线补充审查。

修改日志保存调用前意图与正文快照、预期后版本，执行返回后才确认；崩溃留下 intent/unknown，不能自动撤销。审查只显示路径/哈希/状态，正文留在 0700/0600 私有会话目录。撤销先检查整批路径、当前版本和普通权限，任何冲突先拒绝整批；开始后逐文件记录进度，不声称跨文件原子事务。保存失败必须发生在工具副作用前；结束记录失败则进入未知状态。限制单文件 1MiB，单 run 日志正文配额 16MiB，拒绝超限的新编辑。

审批有效期使用单调时钟；批准返回后复核策略摘要、后端身份、根目录设备/inode 与调用参数。Local 仍为可信宿主执行，最小环境只避免意外继承 Provider/代理/SSH 凭据，不承诺隔离宿主文件或网络。Docker 继续 network=none，不实现未经强制代理验证的域名授权。显式硬工作区磁盘配额请求在当前 bind 后端失败关闭，不把扫描和输出配额称为工作区硬配额。

Docker 的 --worktree 改用固定 commit 的完整独立 clone，不挂载源 .git 或凭据；移除 origin，不继承源仓库 hooks/config，不使用共享 objects/hardlinks。交付从固定 base 比较，包含任务自身 commit 产生的变化，仍保留二进制 patch 与新工作树重放，失败保留副本。Local 的显式 worktree 保持既有行为。

验收：确定性 pytest（冲突/符号链接/损坏日志/配额/审批过期/策略变化/环境过滤/提交后补丁），Ruff/format/mypy/wheel；之后 Rootless Docker 验证独立 Git status/log/commit/二进制重放、断网与秘密环境；官方 DeepSeek 小型真实修复并由控制器独立验收。网络授权/秘密注入和真正容量受限任务盘仍须单独实装验收，不据失败关闭就宣布这些能力完成。

## 最新联合验收与边界

真实结果见 `docs/evidence/B2-delivery-checks.json` 和 `B2-delivery-live.json`，不能以历史首个增量的测试数量代替。控制器日志实际限制为 **16MiB 编码 JSON**，不是允许 16MiB 原始正文后再无界编码。已有文件哈希取自已读取字节，新建 expected_absent 用原子 link 拒绝并发出现的同名文件。原子替换与哈希复核不等于全工作区事务或恶意宿主并发写入的文件系统 CAS。

补丁导出前恢复创建副本时的安全 Git 配置，候选配置单独 0600 保留；拒绝 links/commondir/alternates 等重定向。验证器延续任务后端，Docker 的重放也使用完整独立 clone，验证命令可以在容器中调用 Git；后端未关闭时保留重放目录。所有工具 Git 仍通过 Shell；控制器的固定 clone/补丁/重放是交付维护，不向模型增加逐子命令包装。

`changes/undo` 仅适用当前目录会话的明确文件工具归属，不能用于把隔离副本的 stamp 写回源目录；隔离模式仍用 patch 交付。恢复原字节/普通模式，不声称保留 ACL/xattr、文件身份或撤销任意 Shell 的重命名/删除。Local 不是沙箱；Git 全局配置/Hook/fsmonitor 默认不继承，需要身份时用明确的仓库或命令配置。网络与真正硬工作区存储仍未开放，P3.5 深化仍在计划中；拒绝不支持请求不等于实现这些能力。
