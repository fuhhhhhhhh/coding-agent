# M09 设计：统一工作区与 Docker 任务沙箱

## 范围与完成边界

本阶段新增 `ExecutionBackend`，让 Agent 工具、开发测试、独立验证、取消和产物导出共享一套任务生命周期。实现 Local 与 Docker 两个后端，并把 M06 的验证器升级为“从可信源重建候选，再注入隐藏材料”的独立验证。

本阶段没有实现上下文压缩、worktree、会话恢复、MCP 或多 Agent。Docker 容器共享宿主内核，不等同于 MicroVM。当前机器已通过独立用户 socket 完成 Rootless Docker 验收；结论仅覆盖本文列出的 Linux、cgroup v2 与 rootless 组合。

## 内部数据契约

`ExecutionBackend` 同时提供工具声明、`execute(ToolCall)`、固定 argv 命令、取消、产物导出和关闭。它保持对现有 `ToolExecutor` 的结构兼容，因此权限层与调度层仍能包在执行后端之前。

`find_backend` 只沿包装器公开的 `registry` 链查找后端，并检测循环。Harness 用它管理“权限 → 调度 → 后端”组合中的真实生命周期；权限层也用它核对 `container_mode`，避免策略写着容器、实际却落到 Local 注册表。

`BackendLimits` 保存 CPU、内存、PID、命令时间、输出和产物容量。Docker 将 CPU、内存和 PID 转换为容器创建参数；Local 只能执行命令时限和输出/产物容量，不能声称提供系统资源隔离。

`CommandResult` 区分退出码、超时、取消和 OOM，并分别标记 stdout/stderr 截断。常驻容器里的 exec 子进程 OOM 不会让容器级 `State.OOMKilled` 变为 true，因此 worker 比较固定 argv 或 Shell 工具执行前后 cgroup v2 `memory.events` 的 `oom_kill` 计数，并要求退出为 SIGKILL/137；只有容器主进程异常退出时才读取 Docker 状态。Shell 工具把这一组合稳定映射为 `container_oom`。

`BackendEvent` 只记录后端 ID、容器 ID、调用 ID、结果、耗时和轻量资源数据。它不保存工具参数、命令、环境值或输出正文。传入外部审计目录后，每个事件立即写入 0600 JSONL；工作区内的审计目录会被拒绝。

## 一次工具执行

```text
PermissionedExecutor
  -> ScheduledExecutor
    -> DockerExecutionBackend.execute(ToolCall)
      -> docker exec -i <container> python -m codepilot.workspace.worker
        -> ToolRegistry 参数校验
          -> read/write/edit/glob/search/shell
            -> 同一个 /workspace
      <- ToolResult JSON
    <- BackendEvent（无正文）
```

容器启动后先执行 `describe` 握手。控制器逐项比较容器内外 `ToolSpec`；镜像旧于控制器或工具 Schema 漂移时，容器会被删除，任务不会开始。这避免“模型看到新 Schema、容器却运行旧实现”的隐蔽错误。

## Docker 生命周期与隔离策略

1. 标签解析为本地镜像 ID，后续创建使用不可变 ID；构建镜像的 Python 基础镜像固定到 OCI index digest，Python 依赖带哈希固定。
2. rootful daemon 中容器使用宿主当前非 root UID/GID；rootless daemon 中容器使用 namespace 内 `0:0`，它在宿主上映射为启动 daemon 的普通用户，解决 bind mount 的 subordinate UID 写权限问题。两种模式均使用 `--network none`、只读根层、`cap-drop ALL`、`no-new-privileges`、PID/内存/CPU 限制和 64 MiB 临时目录。
3. 只绑定任务工作区，不绑定 Docker socket，不转发宿主环境变量。模型 SDK 和 API 凭据留在控制器；沙箱没有安装模型 SDK，依赖只含工具 worker 所需的 Pydantic。
4. 每个 trial 只创建一个后端，Agent 工具与开发测试共享该工作区。独立验证另建干净目录和后端。
5. 取消 `docker exec` 时杀死整个任务容器，因为退出 CLI 不能证明容器内进程停止。关闭使用 `docker rm -f -v`，正常、异常和取消走同一清理出口。
6. 容器带 managed、owner、expires_at 标签。新控制器可用稳定 owner 清理同属且过期的遗留容器；标签损坏时保守地不删除。

这些选择对应 Docker 官方公开能力：容器默认没有资源上限，必须显式配置 CPU/内存；`--read-only`、capability、`no-new-privileges` 和网络模式是不同边界，不能用其中一个代替其他边界。Docker socket 不挂载，因为拥有该 socket 基本等于拥有 Docker daemon 控制权。

## 独立验证

`IsolatedVerifier` 保存三个互不混合的输入：可信初始源、Agent 候选工作区、工作区外验证材料。验证时：

1. 复制可信初始源到新临时目录；
2. 按字节计算并应用候选新增、修改和删除；
3. 拒绝源或候选中的符号链接；
4. 拒绝候选预占 `.codepilot-validation`；
5. 最后复制隐藏验证材料；
6. 在新的 ExecutionBackend 中运行固定 argv。

因此 Agent 删除自己看得到的开发测试，不会删除隐藏验证器。验证仍会执行候选生产代码，所以生产代码中的恶意行为需要 Docker 的系统边界约束；“隐藏测试”本身不构成安全沙箱。

## 重要失败场景

- **取消后仍运行**：只杀 Docker CLI 会留下容器内命令。后端取消会 `docker kill` 整个任务容器，并封闭后续执行入口。
- **镜像与控制器漂移**：启动握手比较完整工具 Schema；不一致时删除容器并返回基础设施错误。
- **内存耗尽**：常驻容器内的命令读取 cgroup OOM 计数增量，并与 SIGKILL/137 组合判断；容器级异常再读取 `State.OOMKilled`，避免把普通 SIGKILL 当作 OOM。
- **凭据泄漏**：创建命令没有 `--env`、`--env-file` 或 Docker socket 挂载；审计日志不记录参数和正文。声明工作区内本来存在的凭据仍属于任务可见内容。
- **验证材料篡改**：验证环境从可信源重建，并在候选应用后注入保留目录；候选预占该目录直接判为验证错误。
- **控制器崩溃**：容器标签记录 owner 和过期时间；后续同 owner 控制器清理明确过期容器。
- **日志或产物过大**：两路输出分别排空并截断，产物导出要求普通文件、工作区外目标和独立容量上限。

## 存储边界

当前任务工作区是宿主 bind mount。输出截断与产物容量限制不等于磁盘配额，本实现不作此声明。可写根层被禁用，但工作区可用容量仍由宿主文件系统决定。真实部署应在已验证的 quota、独立卷或受限文件系统上创建 trial 工作区，再把该能力写入支持矩阵。

离线验收：

```bash
uv run --locked pytest -q
```

真实 Rootless Docker 验收：

```bash
export DOCKER_HOST="unix:///run/user/$(id -u)/docker.sock"
docker build -f docker/sandbox.Dockerfile -t codepilot-sandbox:0.1.0 .
CODEPILOT_DOCKER_LIVE=1 uv run --locked pytest -q tests/test_workspace_docker_live.py
```
