# M11 / P2 设计：任务级 Git worktree 与可审查交付

## 范围与产品行为

这一阶段把一次 `task_id` 从“直接在启动目录运行”改成“绑定固定 commit 的独立工作区”。默认产品链
要求源 Git 工作树干净，从 `git_workspace.base_commit` 解析不可变 commit，再在运行状态目录创建
detached worktree。Local 与 Docker 后端都接收任务目录；Docker 仍只挂载该目录，不接触源工作树。

本阶段没有自动合并、后台任务、会话恢复或多 Agent。`--direct-workspace` 只保留为非 Git 目录的显式
兼容入口，启用后不能声称拥有任务隔离或补丁交付保证。

## 数据契约与所有权

`GitWorkspaceConfig` 保存启用状态、起点、源目录干净要求、固定验证 argv、验证时限和补丁大小上限。
`GitTaskWorkspace` 拥有两个路径：Agent 修改的 `worktree/` 和短暂存在的 `replay/`。控制器在
`workspace.json` 记录当前 UID、session/task/run ID、源仓库、固定 commit、工作树路径、状态和补丁
摘要；文件权限为 `0600`。

`GitDelivery` 进入 `ProductRunResult`，明确区分：

- `cleaned`：任务没有修改，worktree 已安全移除。
- `changes_retained`：补丁已导出并在干净起点重放，可选验证也通过。
- `failed_retained`：运行、重放或独立验证失败，原 worktree 和补丁继续保留。

有修改的任务不会被自动删除。显式 `cleanup()` 还会重新核对清单 UID、task ID、绝对路径和当前 Git
状态；只要还有任何修改就拒绝清理。

## 补丁与复验

交付使用 Git 自己的二进制 patch 格式，而不是文本快照。控制器创建临时 index，读取固定 commit，
用 intent-to-add 纳入未跟踪文件，再执行禁用 external diff 和 textconv 的 `git diff --binary
--full-index --find-renames`。因此新增、删除、文件模式和二进制内容都进入同一补丁；补丁受 16 MiB
默认硬上限并以 `0600` 保存，SHA-256 写入交付结果。

随后控制器从相同 commit 建立新的 replay worktree，先执行 `git apply --check --binary`，再实际应用。
项目若配置 `verification_command`，则使用固定 argv 和超时在 replay 目录运行，不接受模型临时更改
复验命令。验证副本完全由控制器创建，完成后可以强制删除；Agent 原工作树只有在干净时才允许删除。

## Git 工具与 Docker 边界

`git_status` 和 `git_diff` 是两个独立的只读工具文件。它们禁用 hooks、external diff 和 textconv，
并限制输出为 256 KiB。Local 后端直接调用同一注册表。Docker worktree 的 `.git` 指针指向控制器的
Git 元数据，该元数据没有挂进容器；因此 Docker 后端只在控制器侧拦截这两个只读工具，文件编辑和
Shell 仍在容器中执行。启动握手只比较容器真正执行的六个基础工具，模型则看到六个沙箱工具加两个
控制器只读 Git 工具。

## 关键失败场景

1. **起点不存在或不是 Git 仓库**：在创建后端、容器和 Provider 前失败，不产生任务工作树。
2. **源工作树有修改**：默认拒绝，因为固定 commit 不包含这些内容，继续运行会造成错误认知；用户需先
   提交、保存，或显式选择兼容直写模式。
3. **补丁无法重放或验证失败**：交付状态为 `failed_retained`，保留原 worktree、补丁及清单，CLI 返回
   非零；不会把模型的“完成”当成可交付成功。
4. **并行任务修改同一路径**：每个 task 使用不同 worktree 和 index，互不覆盖；本阶段不自动合并，
   因此合并冲突留给用户或后续协作阶段处理。
5. **清理路径或所有权不匹配**：拒绝删除；有未提交内容也拒绝自动清理。

## 验收

- 两个任务从同一 commit 并行创建 worktree，分别修改同一文件，源仓库保持干净且两个补丁不同。
- 补丁实际包含新增、删除、可执行位变化和二进制修改，并在干净 replay worktree 通过固定断言。
- 注入 replay 冲突后返回 `failed_retained`，原修改和补丁仍存在，临时验证副本被清理。
- 产品链 fake Provider 在隔离 worktree 写文件，源目录不出现该文件，结果包含复验通过的交付对象。
- 真实 Qwen 与 Rootless Docker 验收结果单独记录，不能由确定性测试替代。
