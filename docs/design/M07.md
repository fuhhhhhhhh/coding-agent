# M07：流式事件与本地 Trace

## 问题与范围

此前 Runner 只接受完整 Message，不能在回复过程中观察增量，也不能检查不完整工具参数。
本阶段保留完整消息历史和原有运行预算，在 Provider 边界增加流式分片组装，在执行链增加关联事件。
未进入 M08 调度、M09 容器或 M10 上下文压缩。

## 数据与调用链

- `contracts/stream.py`：`StreamChunk`、`Usage`、`RuntimeEvent`。
- `providers/stream.py`：`StreamingProvider` 协议与 `collect_reply`。
- `providers/fake_stream.py`：有限脚本、受控异常、离线回放。
- `providers/deepseek.py`：官方 OpenAI SDK 适配 DeepSeek Chat Completions，关闭推理。
- `runtime/loop.py`：兼容 complete/stream，沿用唯一终态、全局调用 ID、预算与取消传播。
- `observability/trace.py`：上下文关联、JSONL、摘要、规范化比较。

运行链：

```text
Provider.stream → collect_reply 按 index 累积 → 显式结束且迭代结束 → 完整 Message 校验
  → 运行内 ID/预算检查 → ToolCallReady → PermissionedExecutor → ApprovalRequested/Resolved
  → ToolRegistry 参数校验 → ToolStarted → 工具执行 → ToolFinished → TurnFinished
  → 下一回合或 RunFinished
```

TextDelta/ToolCallDelta 在收到片段时立即产生；ToolCallReady 是整个模型回复完成校验后的事实，
不是单个 JSON 暂时可以解析就开始执行。实际工具专用 Schema 仍由注册表校验。
同批 JSON、重复调用 ID 等契约错误在首个执行前拒绝，但不同工具的 Schema 不做跨调用事务预检。
单批工具继续顺序执行，不承诺整个批次原子性。

每个 RuntimeEvent 带 run_id、turn_id、sequence；工具事件带 call_id，早期片段可用 call_index 关联。
ToolStarted 在注册表中产生，表示已通过权限及参数检查后进入真实工具；ToolFinished 表示一次执行入口
调用的结果，因此审批拒绝可能只有 ToolFinished 而没有 ToolStarted。自定义 ToolExecutor 若要表示内部
实际开始时间，需要自行调用上下文 emit；Runner 不会把等待审批误标为真实开始。
TurnFinished 覆盖模型及本回合工具；失败、断流、取消也有回合和运行终态。

## 组装和失败边界

- 调用以 index 分开缓存；call_id/name 一旦提供就不能改变，name 不作为字符串片段拼接。
- 每种分片只允许对应载荷；正文、调用参数、用量和结束原因不能跨类型混放后被静默忽略。
- 完整参数必须是 JSON 对象；拒绝重复键、NaN/Infinity、非法 JSON 和重复调用 ID。
- 必须有与调用内容一致的 stop/tool_calls 标记；标记后再发分片也拒绝。
- 原始分片累计编码大小最多 1 MiB；预算超时和外部取消会关闭异步流。
- DeepSeek 适配器兼容 finish 分片附着 usage 和独立 usage 分片；长度截断/过滤/缺失结束原因不执行工具。
- 网络故障转 provider_error，分片契约故障转 contract_error；异常仅记录类型，不保存供应商错误正文。
- 审批等待中取消时，当前和后续工具均不启动。

## Trace 与隐私边界

默认 Runner 只在内存记录。传入 `EventRecorder(directory)` 才持久化，演示入口默认写入已忽略的
`.codepilot-traces/`。文件使用随机名独占创建；JSONL 和摘要权限均为 0600，不使用 run_id 拼路径。
目录应位于 Agent 工作区外；这不是 OS 沙箱，任意 Shell 仍可能访问宿主资源。

底层 Runner 未指定目录时仍只保留内存事件，避免库调用隐式污染工作目录；正式 Local Harness 则要求调用方
提供工作区外 Trace 目录，并为每次任务尝试落盘。这使正式评测满足逐次留痕，同时保持底层组件可测试。

磁盘 Trace 省略整个 text/call 字段，不保存提示词、文件内容、工具参数、工具输出和供应商错误正文。
内存事件及旧 RunReport 仍含完整内容，不能直接序列化为所谓脱敏轨迹。
事件实时追加，结束时另写摘要；没有崩溃恢复或日志数据库事务保证，磁盘 I/O 故障也尚无容错后端。

Usage 用 source 区分 provider/estimate/unknown。没有用量时 Token 为 null，流中断未返回 usage 也未知。
摘要保留每回合用量而非把不同来源相加；本阶段未实现 Token 估算器。
费用、单价来源、单价日期及估算标记均为 null：当前不提供计价，未知不能解释为免费。
上下文压缩在 M10 实现，本轮没有伪造压缩事件。

## 真实 Provider 与预算

DeepSeek 官方指引使用 OpenAI SDK；本次锁定 `openai==2.54.0`，所有 SDK 类型只留在适配层。
参考资料，核对于 2026-10-14：

- https://api-docs.deepseek.com/
- https://api-docs.deepseek.com/api/create-chat-completion/
- https://api-docs.deepseek.com/quick_start/pricing/

用户授权使用 DeepSeek、减少调用。本轮选择低成本 Flash 的非推理模式：模型 ID `deepseek-flash`。
共享 RequestBudget 最多三次请求，每次最多 256 输出 Token，SDK 自动重试关闭；失败请求也计入额度。
额度是实例共享的请求数，不是跨进程的账户费用上限。live 示例只发送固定任务和临时文件，
不发送用户仓库。密钥仅保存在被 Git 忽略的 `.env`，不随代码交付。

真实验证共两次请求、一次 read_file，最终输出 17；供应商计量输入 834、输出 39 Token。
这证明当前非推理流式读取闭环，不证明所有模型、复杂编程任务、思考内容或跨平台兼容。

`docs/evidence/M07-checks.txt` 保存离线检查和演示输出；`M07-live-checks.json` 保存真实运行元数据。
`M07-traces/` 包含成功、相同脚本回放、断流、审批取消以及真实运行的元数据 JSONL 和摘要。

测试覆盖交错分片、跨类型载荷、整批非法 JSON 不提前写入、重复键、非有限数字、错误结束标记、断流、流取消、
超时、审批中取消、默认脱敏、未知用量、规范化回放、SDK SSE/消息转换、请求耗尽和禁用自动重试。
离线回放比较的是行为事件，不是模型任务成功率；脱敏 JSONL 不含正文，不能独自还原原始推理和参数。
