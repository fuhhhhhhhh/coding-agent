## 本轮范围

B3 先落地两个可复用的基础契约：Provider 与摘要请求共享的 `BudgetLedger`，以及 Context 压缩后的持久 `ContextCheckpoint`。它们分别解决“摘要/主请求各自计费导致超发”和“进程退出后压缩视图只存在内存”的问题。完整 Provider 有界重试、事件迁移和复杂崩溃协调继续在本阶段后续增量完成。

## 契约与所有权

- `BudgetLedger` 所有预算状态：请求数、输入 Token、输出 Token。请求前 `reserve_request`，服务端 usage 到达后 `settle`；未知 usage 不回收已占用请求额度。
- `BudgetSnapshot` 只读暴露当前账本，用于测试和后续 Trace；账本不拥有 Provider 客户端，也不自行重试网络请求。
- `ContextCheckpoint` 保存来源摘要哈希、创建时间、压缩前后估算、usage、摘要正文和 `WorkingState`。
- `WorkingState` 从摘要约定标题提取目标、约束、待办、修改、测试证据和风险；它是继续工作的提示视图，不替代 SQLite 中的规范消息事实。
- `CheckpointStore` 只写会话私有目录 `checkpoints/latest.json`，临时文件完成后原子替换，文件权限为 0600。旧检查点在新检查点写入失败时保留。

## 正常轨迹

Runner 准备上下文 → 超过阈值调用摘要器 → 摘要结果通过完整消息校验 → Context 记录压缩事实 → CheckpointStore 原子保存 → Provider 请求继续使用压缩视图 → 会话退出后检查点仍可独立读取。

## 重要失败场景

1. 请求数或输入/输出 Token 预留超限时，在网络调用前拒绝；并发预留不超发。
2. Provider usage 缺失时只保留已预留额度，不把未知成本当作零；后续请求仍受请求预算限制。
3. 摘要正文非法、压缩后仍超目标或检查点写入失败时保留旧检查点，Runtime 不发送已知超预算视图。
4. 检查点 JSON 损坏时明确失败，不回退为空摘要、不覆盖规范消息历史。

## 当前取舍

本轮不把自由文本摘要伪装成完全可靠的语义状态：`WorkingState` 是有界结构化提取，原始摘要和消息仍保留来源。预算账本当前已接入 OpenAI-compatible 流的请求和 usage 结算，最大 Token 配置入口及安全重试策略在后续 B3 增量中接入；默认 SDK 自动重试仍关闭。
