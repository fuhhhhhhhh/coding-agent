# M06：最小评测 Harness 与测试反馈纠错

## 范围

M06 增加 Local 评测层：任务从源目录复制到一次性临时工作区，Fake Provider 驱动已有 Runner，开发测试结果作为反馈，
独立验证器在 Agent 工作区之外决定最终成功。每个任务尝试都记录 Runner 报告、验证结果、变更文件和 unified diff。

本阶段不宣称 Docker 隔离、不接真实模型、不提供 SWE-bench 分数。`TaskSpec` 保存任务 ID、仓库来源/版本标记、描述、环境元数据、
开发测试入口和 Runner 预算；`LocalHarness.run_batch` 顺序运行多个任务，每个任务重新复制干净目录。

## 一次纠错轨迹

```text
TaskSpec
  ↓ 复制干净工作区
ProviderFactory(attempt, feedback)
  ↓
Runner → 开发测试（可被修改，只用于反馈）
  ↓
IndependentVerifier（工作区外固定命令）
  ├── passed → success
  ├── failed → feedback → 下一次尝试
  ├── timeout → timeout
  └── error → unevaluable
```

模型文本结束只是一次候选结束，不能替代独立验证通过。验证失败最多反馈到 `max_attempts`；验证器错误和超时立即停止，避免把基础设施
故障伪装成代码问题。空补丁、删除文件或删除开发测试会由独立验证器重新检查，不能直接获得通过。

## 数据和边界

- `VerificationResult` 区分 `passed`、`failed`、`error` 和 `timeout`。
- `TrialResult.status` 区分 `success`、`unresolved`、`timeout`、`unevaluable` 和 `infrastructure_error`。
- 参考答案和独立验证代码不放进 Agent 工作区；当前演示用固定 Python 命令检查 `calculator.py`。
- 补丁生成是可观察文本证据，不承诺两文件编辑的数据库式原子性。
- 快照只用于 Local 评测和审计；M09 再把验证搬到容器外控制器和独立环境。

## 故障覆盖

测试覆盖首次候选失败后纠错成功、模型提前结束的空补丁、验证器无法启动、验证器超时，以及最大尝试次数耗尽。
还保留现有 Runner 的 Provider 错误、契约错误、时间限制和重复失败保护。

```bash
uv run --locked ruff format --check .

```
