# M02：非流式单 Agent 循环

## 范围与目录

复用 M01 内部契约与 Provider 接口，实现单次运行的历史、顺序执行、错误回传和停止。
没有复制 CoreCoder 实现，没有新增依赖，没有接真实模型。
路线图要求本阶段在 fixture 中读、改、测，而通用工具系统属于 M03，
因此使用仅用于受控验收的固定执行入口，不把它描述为通用文件工具或 Shell。

```text
src/codepilot/
  contracts/models.py         既有类型；补齐 ToolCall.name 命名规则
  contracts/run.py            RunLimits / RunObservation / RunReport
  providers/                 复用 M01 接口和 fake
  runtime/{__init__,loop}.py  循环、状态、额度、停止及错误反馈
  fixtures/{__init__,m02}.py  临时副本、三个固定操作、修复脚本
  m02_demo.py                11 个场景的编排、判据和 JSONL 写盘
examples/fixture_repo/
  calculator.py              故意错误的加法函数
  test_calculator.py         固定 unittest 判据
tests/test_runtime.py        正常循环和故障边界
tests/test_contracts.py      补充命名规则测试
docs/{design,learning}/M02.md
docs/evidence/M02-*.jsonl
docs/evidence/M02-checks.txt
```

contracts 只定义共同数据，不依赖 Runtime。Runner 只依赖 Provider 和 ToolExecutor 接口，
不导入 UI 或 fixture。固定工具在 fixtures 中，防止其受限行为被误认为 M03 通用工具能力。
演示编排、检查与写盘留在 m02_demo，不让 Runtime 负责终端展示和证据路径。

## 最小输入输出契约

`Runner(provider, executor, limits, run_id=...).run(messages) -> RunReport`

- 新运行初始历史只接受非空 system/user 消息序列，不支持恢复历史。
- Provider：`complete(Sequence[Message]) -> Message`，必须返回 assistant。
- ToolExecutor：`execute(ToolCall) -> ToolResult`，参数检查在执行入口，结果 ID 必须匹配。
- 边界重验消息/结果，并深拷贝交给组件的历史、调用和最终报告，避免嵌套参数污染历史。
- 一个 Runner 对应一次运行，不可重用。默认 UUID；演示使用固定 ID 方便对照。

| 契约 | 含义 |
| --- | --- |
| RunLimits | 默认最多 8 次模型请求、16 次工具尝试、30 秒、连续同签名失败阈值 3 |
| RunObservation | run_id、递增 sequence、step、kind，以及消息/调用/结果或终态信息 |
| RunReport | 最终 state/reason、模型与工具计数、完整本次历史、观察记录 |

观察类型为 model_requested、model_replied、tool_requested、tool_result、run_stopped。
这些是完整非流式操作的内存记录，不是 M06 的增量事件体系。
载荷由 Runner 按 kind 填充，未实现外部事件生产者的完整状态机校验。

## 循环、状态与归属

```text
created → running
  请求模型 → 保存合法 assistant 回复
    无调用 → completed
    有调用 → 检查整个批次额度 → 顺序执行 → 加入配对 tool 消息 → 再请求

限制或模型/契约错误 → failed（reason 区分原因）
外部取消 → cancelled，保存 report 后继续传播 CancelledError
```

每次运行只有一个 run_stopped，之后不再请求或启动工具。step 指一次模型请求，
不声称已实现 M06 每回合流式终态协议。
Runner 拥有历史、计数、失败签名和终态；Provider 只响应请求，Executor 只处理单个调用。
工具结果保存为 Message(role=tool, tool_result=...)，与调用一起进入下一次模型请求。
正常修复为 4 次模型请求、3 次工具尝试：读 → 写 → 测 → 最后文本。

## 失败与停止规则

| 触发 | 行为 |
| --- | --- |
| 无调用的合法 assistant 回复 | completed，只说明模型正常结束，不证明任务成功 |
| 请求次数用完 | step_limit，不进行下一次请求 |
| 整批调用超过剩余额度 | tool_budget，该批次一个也不执行 |
| 总时限 | time_limit，取消当前 awaitable，不启动后续操作 |
| 同签名连续失败达到阈值 | repeated_failure，剩余调用不再启动 |
| 未知工具、参数错误 | is_error 结果按原 ID 回传，允许下一次模型纠正 |
| 普通工具异常 | 转为 tool_exception + 异常类型，回传，不自动重试 |
| 普通 Provider 异常 | provider_error，只记录类型，不回显可能含凭据的异常正文，不重试 |
| 非 assistant、ID 重用或结果 ID 错配 | contract_error，不执行重用调用、不回传错配结果 |
| 外部 Task.cancel() | cancelled；runner.report 可检查，CancelledError 继续向上抛 |

失败签名为规范化 JSON 的 [name, arguments]，不含 call_id，键顺序不影响判断。
一次成功或不同失败签名重置计数；持续成功调用仍受步数限制。
不检测任意交替模式的循环，硬上限兜底。工具额度按尝试计，包含无效或未知调用。
当前无 usage 契约，预算不是 token 或费用预算。

时限使用单调时钟与 asyncio.timeout_at；检查点主动 sleep(0)，即使 fake 没有内部 await
也让取消有机会送达。依赖协作式取消，无法强制中断阻塞代码或吞掉取消的组件。
接口依据：[Python cancellation/timeouts](https://docs.python.org/3.11/library/asyncio-task.html)。

## Fixture 判据与限制

prepare_fixture 复制两个文件到新临时目录并加标识；Executor 拒绝未准备的目录。
read_file/write_file 仅接受 calculator.py 与精确参数键，拒绝符号链接和错误路径。
写入内容限制为字符串及最多 4096 字节。run_tests 无参数，固定执行：
当前解释器 `-I -B -m unittest discover -s . -p test_calculator.py -v`。

fake 修复脚本预先写定，不具备真实推理能力。演示检查初始测试失败，
修复后内容等于预定代码且真实测试通过；原 fixture 保持错误版本以便复现。
baseline 轨迹显示 Runtime completed 与 exit_code=1 同时出现，证明终态不能代替任务判据。

固定测试进程取消时 finally kill/wait 回收直接子进程。本 fixture 不生成后代进程；
通用进程树、输出限制留给 M04。接口依据：
[asyncio subprocess](https://docs.python.org/3.11/library/asyncio-subprocess.html)。
fixture 标识与路径约束不是安全沙箱，不可信 Python 内容仍会执行代码，
因此这些工具只用于受控脚本和测试，不用于真实模型或用户工作仓库。

终止可能发生在批次中途，历史可有未执行或无结果的调用，观察记录区分请求与结果。
M02 不提供恢复重放或副作用核对。演示完成后才写 JSONL，不是实时订阅或可靠追加日志。

## 代码注释约定（2026-10-13 补充）

应用户要求，现有 src、tests 与 fixture 的所有函数/方法均补充中文 docstring，说明职责、
输入输出或状态影响。Runtime 和 fixture 的主要条件、异常、停止、额度与资源清理分支，
在分支前补充中文原因说明；代码标识符和协议术语可保留英文。注释解释约束与取舍，
不逐行翻译 Python 语法。

`tests/test_documentation.py` 使用 AST 扫描 `src/codepilot`、`tests` 和
`examples/fixture_repo`，报告缺少 docstring 的文件、行号和函数名。这能机械保证函数级
说明存在，并检查已有 docstring 和行注释至少包含中文；“主要分支是否解释充分”仍需
代码审查判断，避免用脆弱的注释数量规则替代可读性。
该约定已同步写入 AGENTS.md，后续里程碑继续遵守。本次仅改善可读性与守护测试，
没有改变 Runtime 行为，也没有推进 M03。
