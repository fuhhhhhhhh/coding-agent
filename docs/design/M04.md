# M04：文件修改与进程生命周期

## 范围

M04 在 M03 工具边界上增加两类可靠性：文件修改的版本保护和原子替换；Shell 的进程组清理。
本阶段不实现权限审批、容器沙箱、流式事件或真实模型。

## 文件修改契约

`read_file(include_sha256=true)` 会在正文前返回当前 SHA-256；`write_file` 和 `edit_file` 新增可选
`expected_sha256`。调用方可以先读取文件并保存哈希，之后把哈希作为写入前置条件传回：

```text
读取内容 + sha256
       ↓
外部可能修改文件
       ↓
write/edit(expected_sha256)
       ├── 哈希不同：conflict，不产生写入
       └── 哈希一致：同目录临时文件 → fsync → os.replace
```

没有提供哈希时仍允许普通创建或覆盖；这不提供并发冲突保护。编辑工具在读后、写入前再次检查哈希，
缩小外部修改竞态窗口，但无法把普通文件系统操作宣称为数据库事务。

原子写入使用目标文件所在目录的临时文件，因此 `os.replace` 在同一文件系统内完成替换。写入失败时
原目标保持不变，临时文件进入清理分支。`edit_file` 返回 unified diff，供运行轨迹和未来审批界面审查。

## Shell 生命周期契约

POSIX 下 Shell 通过 `start_new_session=True` 建立独立进程组；Windows 使用新的进程组标志。取消或
工具超时时先向进程组发送终止信号，等待短期限后再强制终止，并等待直接子进程退出。stdout 和 stderr
读取任务随后取消或收尾，避免管道任务遗留。

进程组可以终止命令启动的后代，但平台可能暂时保留僵尸记录，且 Windows 的树行为未在本环境验证。
因此文档只承诺当前进程回收及 POSIX 组内运行进程终止，不承诺任意平台 exactly-once 或完整资源隔离。

## 失败场景

| 场景 | 结果 |
| --- | --- |
| 读后文件被外部修改 | `conflict`，不覆盖外部内容 |
| 原子替换失败 | 原目标不变，临时文件清理 |
| 多处匹配或零匹配 | `ambiguous_edit`，不写入 |
| 编辑成功 | 原子替换并返回 unified diff |
| Shell 输出超限 | 继续排空管道，保留上限内输出并标记截断 |
| Shell 超时/取消 | 终止进程组，等待直接进程，清理读取任务 |
| Shell 启动后代 | POSIX 组信号覆盖运行中的后代；僵尸回收和 Windows 行为需单独验证 |
