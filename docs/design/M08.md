# M08：受限并发与取消传播

## 范围与参考风格

M08 在权限层之后、工具注册表之前加入独立调度器。Runner 只有在执行器显式声明支持安全并发时才并发提交同批调用；
普通执行器继续保持原有顺序语义。本阶段不实现 Docker、上下文治理、后台任务或完整 CLI。

实现风格参考 Claude Code 对外公开的交互原则，而不假设或复制其内部实现：工具权限先于执行、只读操作更容易自动允许、
修改和命令采用更保守的控制，以及 JSON/stream-json 事件适合程序化观察。参考：

- https://docs.anthropic.com/en/docs/claude-code/cli-usage
- https://docs.anthropic.com/en/docs/claude-code/security

CodePilot 仍使用自己的内部契约、调度算法和测试证据。

## 数据流

```text
完整 ToolCall 批次
  ↓ PermissionedExecutor：allow / deny / ask
  ↓ ScheduledExecutor.plan：实际路径 + effect + 声明资源
  ↓ 可取消队列：容量、活动冲突、同资源先到顺序
  ↓ ToolRegistry：参数 Schema 校验和工具超时
  ↓ ToolResult：按原 ToolCall 顺序写回消息历史
```

`ExecutionPlan` 只包含调用 ID、访问模式和资源键。文件调用从实际 `path` 生成动态资源键；glob/search 等宽范围读取使用
`workspace`；Shell、未知工具、非法路径以及不能解释资源的写入使用 `exclusive`。权限包装器通过下游的工具目录判定，
审批完成后才进入调度队列。CLI 审批使用单输入锁，避免并发提示交错。

## 冲突规则

- 两个纯读取可以共享资源，但仍受 `max_concurrency` 限制。
- 同一路径只要包含写入就冲突；不同精确路径的写入可以并行。
- 工作区宽范围读取与任意写入冲突，不声称读取一致快照。
- `exclusive` 与所有活动计划冲突；Shell 和未知工具默认独占。
- 后到调用不能越过与自己冲突的先到等待项；无冲突调用可绕过，避免全局队首阻塞。

## Runner 与事件

Runner 对无调度能力的执行器继续逐个调用，并保留连续失败时立即停止的旧行为。对 `supports_parallel=true` 的执行器，
同一模型回复中的调用各自进入任务；`tool_finished` 按真实完成顺序发布，工具结果仍按模型调用顺序和 `call_id` 写回。

新增 `tool_queued`、`tool_scheduled`、`tool_queue_cancelled`。内存事件保留动态资源键，落盘 Trace 将 `path:` 后的实际路径
替换为 `<redacted>`，避免调度可观察性重新泄漏工具参数。

## 取消与故障边界

- 排队或锁等待取消：移除等待项并唤醒后来者，工具不会启动。
- 运行中取消：调度器在 `finally` 释放资源；Shell 继续使用 M04 的进程组清理。
- 同批任一契约故障：Runner 取消其余仍排队或运行的任务并等待清理。
- 并发批次中的工具可能已经产生独立副作用，不能把批次描述成事务；连续失败只在结果按原顺序汇入后判断。
- 同文件读改写由动态路径锁串行；外部进程绕过调度器的写入仍依赖 M04 哈希前置条件检测。

## 验收

```bash
uv run --locked ruff format --check .
uv run --locked ruff check .
uv run --locked mypy src tests
uv run --locked pytest -q
uv run --locked python -m codepilot.m08_demo
git diff --check
```

当前 Linux/Python 3.14.7 环境通过 130 项测试。覆盖读取真实重叠、同路径 FIFO、同文件读改写不丢更新、排队取消、
结果顺序与完成顺序分离、动态路径脱敏，以及 Runner 取消时活动 Shell 清理和排队读取不启动。
Windows/macOS 的并发进程取消、真实交互终端中的并发审批尚未验证。
