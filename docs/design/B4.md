# B4：扩展与后台协作

状态：在 Linux Local、Rootless Docker、官方 DeepSeek Flash Chat 的明确范围内通过受限验收；不代表远程/有状态 MCP 或写 Agent 已通过。

## 统一产品链

一次交付 Skills/作用域规则、受控 Hooks、stdio MCP、后台任务与只读 explore/review 子任务。
默认关闭可执行扩展，只读技能元数据可发现；仓库不能配置任意 Hook/MCP 命令或扩大权限。
普通任务仍直接工作在启动目录，Git 经原生 shell；不实现多写 Agent、团队或远程 MCP。

- ExtensionConfig：可信用户配置决定是否启用及 Hook/MCP 命令和能力上限；项目只能整体禁用。
- SkillRecord：名称、描述、相对来源、内容哈希；Prompt 只带元数据，load_skill 校验后按需读取。
- HookRecord：before_tool/after_tool、不可变 argv、有限超时；不允许改参数，独立审批与调用计数。
- MCP：官方 SDK 仅适配边界；stdio 进程位于所选执行后端，单消息/目录/结果有界，Schema 漂移拒绝，断开未知副作用不重试。
- TaskRecord：父 run/call、任务 ID、状态、输出游标、资源、预算及结束原因；SQLite 事件持有事实。
- 后台任务归当前前台运行所有，退出时取消并清理，重启不复活；前台读取不保证后台写入的稳定快照。
- 只读子任务复用 Runner 与 Provider 的共享 RequestBudget，只暴露读取工具，禁止 Shell/写入/再委派；独立步骤/输出上限、父取消传播。

## 重要故障与验证

覆盖：技能链接逃逸/超长正文/来源变化；项目越权配置；Hook 超时/拒绝/非法返回；MCP 同名、Schema 变更、断开与大结果；后台排队/取消/退出/崩溃；子任务预算、权限及父取消。
先离线确定性 pytest/Ruff/格式/mypy/wheel，再 Rootless Docker，再官方 DeepSeek Flash 有界真实链路。
真实本轮最多 48 次模型请求，主请求与子任务/摘要计入同一额度；不打印密钥。
模型自述、工具结果、Runtime 终态和控制器独立验收分别记录。

## 实现与状态所有权

`CodePilotApplication._execute` 把原执行后端包成 ExtensionRouter，再装配 Context、调度和权限。
ManagedExecutor 在同一个权限入口外组织 Hook，内部调用仍逐次审批、调度、计数和记录；不另写 Agent 循环。
默认 `extensions.enabled=false`，`skills=true`：只发现资料，不启动仓库程序。

- `extensions/models.py` 保存可信配置；项目配置只接受 `extensions: {enabled: false}`。
- `skills.py` 最多发现 32 个、每个 32 KiB 的技能；描述与哈希进入上下文，正文按名称加载。
  正文是资料，不能改变权限。嵌套 AGENTS 按外层到内层给出来源，单文件 8 KiB、总量 16 KiB；
  更具体的任务指引覆盖一般指引，但用户授权和系统边界始终优先。链接、逃逸、非 UTF-8、版本漂移拒绝。
- Hook 仅 before_tool/after_tool，固定 argv 最后附一份事件 JSON 参数；只能返回 decision/message。
  不支持改参数。每次 Hook 单独审批并共享实际操作额度，不递归触发；子代理不运行进程 Hook。
  after_tool 拒绝必须说明原工具已经完成，不能诱导模型重放副作用。
- MCP 用官方 Python SDK 1.30.0 的 ClientSession；传输限制 64 KiB/消息、8 条队列，
  最多 32 个工具、8 KiB/Schema、48 KiB 目录/结果。拒绝远程 Schema 引用。
  server/tool 双层命名空间；call 前重新列举并与快照严格匹配，不采信只读注解作为授权。
  每次 list/call 使用一个新服务器和独立受控后端，因此只支持无跨调用内存依赖的 stdio 服务。
  Docker 下在任务容器中启动，不能找不到服务就退回宿主；默认断网仍生效。
  服务端 stderr 只排空，故障只报告类型与未知结果，不泄漏原始错误或自动重试。
- `tasks/manager.py` 持有当前 run 的句柄、任务 ID 与 SQLite 记录；状态 queued/running/
  succeeded/failed/cancelled，真实崩溃后协调为 unknown。当前没有需要 waiting 的外部审批托管状态。
  日志最多 16000 字符、每页 4000；完整命令输出复用 OutputStore 配额与读搜。
  任务的实际 backend/进程归属先持久登记。清理失败阻断正常结算，不能清空未确认资源。
- 子任务复用 Runner 和 Provider 适配器；ChildBudget 消耗同一个父 RequestBudget、Token 账本及
  SQLite 请求次数，同时有自己的请求/步骤/工具限制。仅父工具目录与固定读取集合交集，禁止递归。
  子轨迹独立记录，不混入父规范消息；返回模型报告、来源 call_id 和 independent_verdict=not_run。
  父模型仍须实际修改、测试并核对，不把子报告升级成已验证事实。

## 调度与取消：本轮实际修复的两类死锁

后台命令返回 ID 后，原工作区租约保留到实际完成。允许前台读取，但不保证读取稳定快照；
写操作、其他进程继续保守等待。状态、取消、输入属于内部可信控制声明，可以绕过写等待和容量限制，
避免“取消请求等待被取消者释放资源”。模型和 MCP 声明不能获得这种调度特权。

只读子任务的外层 delegate **不保留读租约**：每次子读取自行调度。如果父 Hook 等待外层读租约，
而子读取又因公平队列等在 Hook 后面，会形成循环等待。首次真实 DeepSeek 联合测试发现该问题；
修复后用延迟子读取的屏障回归，再重新真实验收。失败尝试计入本轮总预算；初始 24 次不足，按用户高预算授权扩为 48 次总上限，没有重置隐瞒。

父任务退出时先关闭控制监听，再取消/等待子任务和独立后端，最后释放延迟租约及父后端。
取消清理用现有 settle，完成后仍传播调用方的新取消；否则控制监听器会吞掉取消并使退出挂住。

## 交互与持久化

模型使用 task_start/status/cancel/input、delegate；终端 `/tasks` 查看当前会话任务。
运行中可在另一个终端 `codepilot tasks list SESSION`、`show SESSION JOB`、`cancel SESSION JOB`、
`input SESSION JOB`。控制器消费 0600 私有信箱，核验 parent_run/任务归属后执行；输入不进入命令行参数，
TTY 用不回显输入并附换行，非 TTY 保留输入字节。每次最多消费 32 条，消费后删除；失败只记事件类型。

PTY 只用于 interactive=true，支持输入/EOF/窗口尺寸，单次输入 4096 字节。
宿主 PTY 关闭回显；Docker 第二层 PTY 也明确 stty -echo。程序主动打印输入仍属于程序输出，
不能保证任意程序永不泄漏。任务完成保留有界日志与原文引用，不能用最终退出码覆盖日志。
没有完整全屏 TUI、任意运行中目标编辑或脱离前台永久托管；Ctrl-C 停止当前 run 后再输入新目标。

持久化复用 B1/B3 SQLite，不新建平行会话库。重开不复活后台进程/服务器/模型请求；
running 或未知副作用继续 needs_reconciliation，先核验资源再协调，不重放写入。

## 边界与参考

Local 是用户信任的宿主执行；Docker 继承现有隔离范围。未补齐 B2 网络/秘密、磁盘硬配额、
worktree+Docker Git、安全撤销，不因扩展接入而扩大安全承诺。远程 MCP、OAuth、长连接状态服务、
写子代理、团队/合并、外部目标运行中 steering、Windows/macOS 和完整终端作业控制均未验收。
没有提供跨调用去重的异步通知服务；当前用户主动轮询或发送控制消息，不声称通知 exactly-once。

官方参考：https://github.com/modelcontextprotocol/python-sdk （2026-10-19 核对；main 的 v2 说明
与当前锁定的 v1 不同，按实际 1.30.0 API/源码实现）。JSON Schema 使用 jsonschema 官方库，
不自行写 Schema 验证器。没有复用 Claude Code/Codex 私有实现，只采用当前目录、简单工具和明确审批原则。

```bash
uv run --locked pytest -q --basetemp=/dev/shm/codepilot-b4-final
uv run --locked ruff check src tests
uv run --locked ruff format --check src tests
uv run --locked mypy
uv build --wheel
```

本机存储负载导致 SQLite fsync 长等待，确定性测试临时目录使用 tmpfs；这是测试环境选择，
不是进程掉电持久性证据。真实崩溃测试是控制器 os._exit，不能据此承诺物理掉电零丢失。
最终命令、计数、真实模型四层结果和未运行项见 `docs/evidence/B4-checks.txt`、`B4-live*.json`。

## 当前目录结构及分层原因

```text
src/codepilot/
  app/service.py             统一装配和退出顺序
  extensions/                技能/规则、可信配置、Hook/MCP 及工具路由
    models.py skills.py router.py executor.py mcp.py
  tasks/                     当前 run 拥有的任务、PTY、控制消息、只读子 Runner
    manager.py terminal.py controls.py children.py
  permissions/ scheduler/    延用原授权、Action 指纹与资源租约
  sessions/ context/         延用 SQLite 事实、输出和共享预算/上下文
  ui/cli.py                  管理入口，只消费事实与发送控制
examples/extensions.yaml     显式可信配置示例
tests/test_b4*.py           确定性与显式 Docker 真实验收
docs/design/B4.md           契约和边界
docs/learning/B4.md         推荐阅读轨迹与三道问答
docs/evidence/B4-*          两次失败及最终联合验收
```

extensions 负责“请求具有什么含义、能否进入执行链”，tasks 负责“启动后由谁持有和清理”。
权限、调度和存储留在原模块，避免各个扩展重建审批、数据库或模型循环。目录只为已运行的机制创建，
没有预建团队、写 Agent、远程 MCP 的空实现。
