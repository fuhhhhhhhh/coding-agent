# M10 设计：两层上下文治理与按需代码定位

## 范围与参考风格

M10 解决长任务中的两个不同问题。第一层把大型工具输出移出模型 prompt，但保留可验证的原文、错误线索和分段读取入口；第二层在历史接近输入预算时，把旧的完整工具回合压缩成结构化摘要，同时保留仓库规则、任务信息和近期完整回合。

实现风格参考 Claude Code 的公开交互原则：仓库规则在任务中持续生效；代码通过搜索和读取按需装配；接近上下文窗口时自动压缩，也允许显式 compact；压缩对用户可观察但不声称无损。本项目没有复制 Claude Code 内部实现，也没有加入其未公开的算法。

本阶段没有实现跨进程会话恢复、长期 Memory、向量检索、worktree、Skills 或 MCP。ArtifactStore 的索引仍在当前进程内，跨进程恢复属于后续阶段。

## 最小目录与职责

```text
src/codepilot/context/
  assembly.py    # 仓库规则和任务信息的初始消息装配
  models.py      # 预算、引用、切片、摘要、视图和轨迹契约
  artifacts.py   # controller-owned 原始输出存储和范围读取
  summarizer.py  # 摘要协议及复用 Provider 的适配器
  manager.py     # 工具结果治理、prompt 视图、自动/手动压缩
src/codepilot/runtime/loop.py
  # 每次 Provider 请求前获取 ContextView
src/codepilot/m10_demo.py
tests/test_context.py
```

ContextManager 同时实现工具目录包装器和 prompt 视图构造器。推荐组合顺序是：

```text
ExecutionBackend / ToolRegistry
  -> ContextManager
    -> ScheduledExecutor
      -> PermissionedExecutor
        -> Runner(executor=PermissionedExecutor, context=ContextManager)
```

这样 `read_context_artifact` 仍经过调度和权限层，普通工具结果在 ContextManager 返回 Runner 前完成落盘。ContextManager 继续公开 `registry`，已有 `find_backend` 可以沿包装链找到 Docker 后端。

## 内部数据契约

- `ContextSeed` 与 `RepositoryRule`：把规则来源、规则正文和任务信息分开。规则生成独立 system 消息，任务生成 user 消息；它们构成压缩时不可删除的前缀。
- `ContextLimits`：保存最大输入、回答预留、自动触发值、压缩目标、近期回合数、大输出阈值、预览和读取上限，并校验 `target < trigger <= max - reserve`。
- `ArtifactReference`：只公开随机 artifact ID、来源 call ID、字符数、字节数和 SHA-256，不公开宿主路径。
- `ArtifactSlice`：描述 `[start:end]` 字符范围、总字符数和 `has_more`，避免 UTF-8 字符被字节切片截断。
- `ContextView`：只表示本次 Provider 实际看到的消息和估算 Token；它不覆盖 Runner 的规范消息历史。
- `SummaryResult`：摘要正文与该次摘要调用的 `Usage`。未知用量保持 unknown，不按零成本处理。
- `ContextRecord`：只记录 artifact/压缩类型、ID、容量、压缩前后估算及 usage，不记录工具正文或摘要正文。

## 第一层：大输出落盘

普通工具先由下游执行器完整执行。结果 UTF-8 字节数超过阈值后：

1. `ContextArtifactStore.write` 使用随机 UUID 文件名和 `O_EXCL` 创建 0600 文件；写完执行 `fsync`，成功后才把引用加入内存索引。
2. Prompt 中的 ToolResult 被替换为短引用，包含来源 call ID、字符/字节范围、SHA-256、行数与首行概览、固定长度头尾和最多八条有界错误线索。
3. 中段线索从完整输出扫描 `error/failed/exception/traceback/fatal/assert`，每行和总行数都有上限，避免一条超长错误重新撑爆 prompt。
4. 模型可调用只读工具 `read_context_artifact(artifact_id, start, max_chars)` 分段读取。该工具只接受当前 store 登记的 opaque ID，不能借此读取任意宿主路径。
5. 磁盘写入失败时返回原始 ToolResult，并记录 `artifact_write_failed/context_degraded`。系统不会制造一个不存在的引用；如果原始结果随后超过 prompt 硬预算，Runner 会明确以 `context_limit` 停止。

ArtifactStore 保留文件直到调用方显式执行 `cleanup()`。本阶段不自动在 Runner 结束时删除，因为运行报告中的引用可能仍需检查；生产会话的保留和恢复策略留给会话持久化阶段。

## 第二层：预算与压缩

`estimate_message` 将 ASCII 按约四字符一 Token、非 ASCII 按约一字符一 Token 估算，并加固定消息开销。它用于提前控制，不冒充特定模型 tokenizer；Provider 返回的真实 usage 与本地 estimate 仍由 `source` 区分。

每次 Provider 请求前，Runner 调用 `ContextManager.prepare`：

1. 单条消息若已超过 `max_prompt_tokens - response_reserve_tokens`，直接停止。拆分或摘要唯一用户约束可能改变语义。
2. 总估算低于 trigger 时返回规范历史的深拷贝。
3. 超过 trigger 时，连续初始 system/user 消息作为不可删除前缀；其余历史按 `assistant + 它的全部 tool result` 分组。
4. 保留配置数量的近期完整组，只把更旧的完整组交给 `Summarizer`。不完整、错配或孤立 tool 消息会被拒绝。
5. 摘要作为标记明确的 system 消息插在前缀和近期历史之间。摘要后必须低于 target，否则以 `context_limit` 停止，不把超预算请求交给 Provider。
6. 相同旧历史的摘要按规范消息哈希缓存；缓存命中记录零新增估算 usage，避免重复调用摘要模型。

`compact(messages)` 提供手动入口，复用完全相同的分组、摘要和预算验证。压缩只改变 `ContextView`；`RunReport.messages` 仍保存逐条规范历史，因此原始运行证据和 prompt 视图不会互相覆盖。

## 可观察轨迹

Runtime 增加三个元数据事件：

```text
context_artifact_written(artifact_id, call_id, original_bytes)
context_compacted(tokens_before, tokens_after, usage, outcome=model|cache)
context_degraded(outcome/error_type)
```

默认 JSONL 仍不保存原始输出、摘要正文、用户约束或工具参数。ContextManager 另外保留 `ContextRecord`，供测试和未来 UI 展示压缩成本。

## 重要失败场景

- **Artifact 不存在**：未知 ID 或已清理文件返回配对的 `tool_error: artifact_not_found`，不回显宿主路径。
- **磁盘写入失败**：保留唯一原始结果并记录降级；不会用悬空引用替换正文。
- **中段才有错误**：固定头尾之外扫描有界错误行；演示中的 `MIDDLE_ERROR` 位于 110KB 输出中段，短引用仍可定位并按范围读取。
- **摘要调用失败**：记录异常类型而不记录异常正文，以 `context_limit/summary_failed` 停止；不会静默发送超阈值历史。
- **摘要仍过大**：`summary_above_target` 明确停止，不继续删除初始约束或拆散近期工具回合。
- **单条消息超限**：`single_message_too_large` 在 Provider 请求前停止，Provider 请求次数仍为零。
- **调用/结果错配**：压缩分组检查每个 call ID 和 tool result 顺序，错配历史不进入摘要器。

## 验收结果与边界

离线演示使用同一个固定 110,039 字节日志任务比较基础策略和治理策略。两者都定位到中段错误；基础策略两轮 prompt 本地估算合计 27,657 Token，治理策略三轮（包含一次按需读取）合计 1,001 Token，最大单轮 562。该数字是同一估算器下的受控对照，不是供应商账单，也不是模型成功率。

摘要器接口和 `ModelSummarizer` 已实现，但本阶段没有再次消耗真实 API；测试与演示使用确定性 fake 摘要。真实模型的摘要质量、不同 tokenizer 误差、跨进程 artifact 恢复和磁盘配额仍未验证。
