# B5：真实任务评测与可审查交付

状态：终端/评测/安装交付链在明确支持范围验收；成熟发布门槛仍阻断。

本轮一次交付终端维护操作、统一产品评测、版本锁定和独立验收、安装/支持与发布门槛。
现有 LocalHarness 是历史机制测试，不作为产品完成证据；新评测直接调用 CodePilotApplication。

## 契约与验收前冻结

- Suite：任务清单/来源完整 commit/参数/配置/隐藏材料哈希、重复次数、总请求上限和成功目标。
- Trial：独立 checkout、初始 dirty 文件、修改前字节及模式快照、模型自述、工具事实、Runtime、独立 verdict。
- 独立验证器只在 Agent 退出且后端关闭后，在新副本注入隐藏材料；禁止改保护文件、空修复蒙混通过。
- 管理操作无模型请求；测试仍经过原权限/调度/会话/超时链，命令成功不等于需求验收。
- doctor 仅读；resources prune 默认预览，持会话锁、核验精确 UID/PID 起点/容器标签，不删除工作区文件。
- 模型/仓库/镜像/清单漂移不混算；中断留下 trial started 记录，不能恢复后重跑未知任务。

先确定性 pytest/Ruff/格式/mypy/wheel，再 Rootless Docker，再官方 DeepSeek Flash。
真实评测：tomli src 布局、boltons 包布局的固定来源，人工注入回归（不是宣称修复了上游现存 bug），
每任务三次独立 trial；单次最多 16 请求、8192 输出 Token，总请求硬上限 96。目标六次全部独立通过；
未达标保留全部结果，不事后删除失败。小样本不宣称统计优势。

重要失败：无补丁/删测试/越界改动；校验器超时/不可启动；版本漂移/错误 seed；请求耗尽/渲染失败；
取消后残留；资源身份不符拒绝；磁盘写失败不覆盖旧报告。B2 未通过边界进入 release gate，不静默宣称成熟发布。

首轮实际 83 请求：5 个候选独立通过，1 次验证器因镜像标签更新导致旧索引丢失而不可评测；原分类还误把 step_limit 的独立成功记为 unresolved。保留完整首轮结果，修复分类和镜像引用租约。第二轮运行前重新冻结六次任务，各最多 24 请求/24 步、总上限 144，首轮与第二轮不混算，也不声称同预算优化。

## 已实现的操作面

`codepilot doctor` 只读检查 Python/包版本、Git/rg/Docker、工作区读写、状态目录可写父目录和剩余空间，
Docker 模式记录 daemon/存储驱动/rootless 与镜像 ID。不访问 Provider，不修复/重启公共服务。
`diff` 使用原生 Git 查看暂存、未暂存及未跟踪索引；禁用外部 diff/textconv/fsmonitor/Hook，
输出有截断标志。它展示整个工作区，不能把所有变化说成某个模型 run 的贡献。
非 Git 目录明确没有 Git diff，仍可通过 sessions facts 检查版本化事实。
`permissions` 展示实际权限预设与扩展开关，不读密钥。交互有对应 /doctor、/diff、/permissions。

`test --timeout 120 -- python3 -m unittest` 是用户明确命令，先按 argv 正确引用，再提交原 shell 工具。
它走相同 Router/Context/权限/调度/输出/会话，直接执行一次 ToolCall，不调用 Provider 或伪造模型请求。
事实事件增加 command_requested，steps=0、execution_source=user_command、request_attempts 不增加；
Trace 有工具与唯一结束事件。command_succeeded 只表示命令退出 0，independent_verdict 仍为 not_run。
Shell 显式时限支持 0—900 秒内正数，绑定审批并受总运行时限；未传时保持原工具默认值。
测试新建自己的会话，不把可能修改测试产物的命令伪装成只读维护。/test 取消后可继续输入。

`resources prune SESSION` 默认预览。--apply 才发送精确清理：持会话锁；UID、PID 启动时钟和独立
进程组匹配；容器 ID、managed/owner 标签匹配。二次检查避免误杀复用 PID，不操作公共 daemon，
不删代码/worktree/补丁，不自动把未知调用改成成功；物理清理后仍需显式 reconcile。

TTY 审批不用阻塞 input 线程：规范模式用 asyncio 监听一行/EOF，取消后移除监听。
非 TTY 审批直接拒绝，避免吞脚本输入。渲染器在审批期间有界缓冲工具进度，全部审批结束后再展示；
JSONL 事件不缓冲。卡片按终端宽度和中文显示宽度对齐；最终展示会话累计 usage/未结算与费用是否未知。
product_started/product_result 带 schema_version=1，原字段保持兼容。原子编辑保留普通权限位/执行位，
不复制 setuid/setgid 等提权位；新文件保持私有默认。ACL/xattr/物理掉电不在本轮保证范围。

## 正式评测路径

旧 `LocalHarness` 保留给历史机制回归；正式 `codepilot eval MANIFEST --output DIRECTORY` 调用
`evals/product.py:ProductHarness`，每个 trial 进入 `CodePilotApplication.run`。清单是可信执行材料：
验证命令也会执行代码。--approve-tools 明确选择有限批量授权；默认拒绝待审批工具。
HTTPS 仓库下载还需 --allow-download，只在控制器获取；工具容器仍断网。所有 Git 操作仍经 CLI，
没有给模型新建逐子命令 Git wrapper。

1. 新建不可覆盖的 0700 输出目录，冻结任务/配置、隐藏材料哈希、包源码哈希和环境；秘密不进入清单。
2. 源完整 commit 必须精确命中；控制器 clone 后 detached checkout，逐条 seed 仅允许一次精确匹配，
   再叠加用户已有 dirty 文件。快照记录字节哈希/权限/大小；最多两万文件、256 MiB，拒绝链接/特殊文件。
3. 隐藏材料冻结到私有目录，不进入 Agent 挂载。先在新验证副本证明初始缺陷失败，坏验证器直接记
   unevaluable 且零模型调用。正式候选结束后再重建基线，仅覆盖允许修改文件，最后注入隐藏脚本。
4. 每 trial 独立会话，父模型/摘要/子请求共用原预算；清单所有最大请求之和不得超过 suite 上限。
   保护文件被修改、无实际修复、Git 起点/暂存区/执行配置变化均不能混成成功。
5. 记录模型自述、版本化工具事实、Runtime reason 和独立 verdict。任务成功以独立判据为准，
   Runtime 步数耗尽可以与代码独立通过同时出现，分别统计，不用 completed 替代任务结果。
6. 每 trial 先落 started，再落不可混淆的结果；中断剩 started/无结果表示未知。拒绝复用输出目录，
   不自动重放。报告原子替换，写失败不覆盖旧报告；磁盘硬容量边界仍属 B2 遗留。

默认保留所有工作区、完整基线、初始/候选 Git diff、会话与结果，便于审查；不自动删除候选劳动。
汇总仅嵌入变更文件的基线与完整基线哈希，避免重复复制真实仓库索引。相对清单路径相对清单目录解释。
Git diff 相对 upstream HEAD 可以为空：修复注入的未提交回归刚好恢复 HEAD。是否实际修复应对比
**注入后用户基线**，不能仅凭 Git diff 空或模型声称成功判断。

## 镜像引用与真实发现

仅固定镜像 ID 不足：本机更新同名构建后，旧 manifest 索引可能失去引用，后续验证器无法启动。
评测现在创建唯一 codepilot-eval-UID-UUID:pinned 别名保留引用，所有主/隐藏验证器固定相同 ID；
结束/取消只删除自己创建的别名。计划记录别名，崩溃后的残留可定位，禁止执行公共 image prune。

首轮的最后一次验证器故障就是本轮并行更新镜像暴露的真实失败；原始 4 success / 1 unresolved /
1 unevaluable 报告保留，不能覆盖为成功。计数修正后，步骤耗尽但独立通过仍是任务成功；
另一候选换新镜像独立复核通过只作为诊断，不混入首轮通过率。第二轮另行冻结完整六次。

## 测量、比较与发布

记录实际请求/Token/未结算/估算费用、总耗时、首个请求至正文时延、工具排队 sum/max/count、
私有 Artifact 总字节、容器采样内存峰值及控制器进程累计高水位。后者包含先前 trial，
不是独立每次的真实峰值；容器采样也不声称捕获每个瞬间。无 usage 时不按零计算。

`eval-compare A/report.json B/report.json` 校验 plan 指纹、完整性、任务/隐藏材料/预算/模型/平台/镜像。
不匹配拒绝比较；匹配只给描述性差值/中位耗时，不宣称小样本统计优势。

release_ready 与 task_gate_passed 分开。B5 可以证明选定任务链通过，但 B2 的网络/秘密、
工作区硬磁盘配额、worktree+Docker Git、安全任务撤销仍阻断“成熟发布”。不因真实样本通过就将
这些边界改成已实现，也不自动发布 PyPI。当前交付为可审查的 Linux Local/离线 Rootless Docker 开发版。
CI 只运行确定性检查及仓库外 wheel 检查，不注入模型密钥；远程 CI 状态以实际结果为准。

## 目录与验证

```text
src/codepilot/app/operations.py   只读维护与用户命令，共用正式执行链
src/codepilot/evals/product.py    清单、版本/任务所有权、独立验收、比较与门槛
src/codepilot/ui/                 命令发现、审批期间的显示、带版本结果
src/codepilot/permissions/        TTY 可取消审批，原 Action 边界不变
src/codepilot/tools/              Shell 时限及编辑权限保留
examples/evals/                  固定真实任务与模型不可见验证材料
.github/workflows/ci.yml          无密钥的确定性/安装矩阵
```

主要验收命令：pytest、Ruff 全目录、格式、mypy、wheel；Rootless Docker 既有 8 项加 B5 正式链；
Python 3.11 干净 wheel 的仓库外完整检查；真实官方 DeepSeek 六次重复。具体输出与未运行项见 B5 evidence。

第二轮实际六次独立通过、六次 Runtime completed，共 62 请求；两轮共 145。完整结果见 B5-real-report.json。没有把新镜像复核结果改写进首轮，也没有混算两个预算下的成绩。

安装深化：Python 3.11 首轮曾有事件循环关闭后 subprocess transport 析构警告；用 500000 字节
输出暂停 PIPE 稳定复现“进程已退出但 transport 未关闭”。stop_process 在确认组停止后显式关闭
CPython transport 并让回调收尾；在 3.11/3.14 把 PytestUnraisableExceptionWarning 升为失败后通过。
此处隔离一个高层 Process 无 close 的实现边界，不承诺其他 event loop/实现已经验收。
终端 BrokenPipeError 不再被 Context 误转为可重试的 output_capture_failed，异常停止并保留未知意图。
