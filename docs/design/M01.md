# M01：工程骨架与内部契约

## 问题与范围

为后续 Runtime 提供可校验、可序列化的供应商无关数据边界。
起始仓库没有代码，因此本轮新建最小包，而非重复已有能力。
没有从 CoreCoder 或其他 Agent 仓库复制实现。

```text
pyproject.toml / uv.lock       安装、依赖与检查配置
codepilot.example.toml         显式离线配置
src/codepilot/
  config.py                   配置入口
  contracts/models.py         五类内部契约
  providers/base.py           Provider Protocol
  providers/fake.py           有限脚本实现
  demo.py                     两次独立请求的验收入口
tests/                        契约、配置、fake 故障测试
docs/{design,learning,evidence}/
```

未创建后续模块的空目录或占位类。

## 内部数据契约

| 类型 | 输入与输出含义 | 本轮约束 |
| --- | --- | --- |
| Message | role、content、tool_calls、tool_result | 只有 assistant 可带调用；tool 必须带结果且无重复正文；拒绝空消息 |
| ToolCall | call_id、name、arguments | ID 至少含非空白字符；名称为 ASCII 标识符（M02 时补齐）；参数为完整 JSON 对象；同条消息 ID 唯一 |
| ToolResult | call_id、content、is_error | 成功或失败内容通过同一类型传递；允许空输出 |
| AgentEvent | session/run/turn ID、sequence、kind、message | 本轮 kind 仅 message_received；序号为严格正整数；整条消息可 JSON 往返 |
| RunState | created/running/completed/failed/cancelled | 仅状态词汇；没有状态转换函数 |

Contract 使用严格类型、拒绝额外字段、拒绝非有限浮点数，顶层字段冻结。
JSON 解码通过 `model_validate_json`，因此 JSON 数组可以还原 tuple；
直接传 Python 数据时则要求 tuple。工具参数中的 dict/list 仍可原地修改，
冻结并非递归不可变；应在跨组件边界构造新值，fake 对输入脚本做深拷贝。
不使用 `model_construct` 绕过校验。

工具参数的 JSON 合法性不等于工具 schema 合法性；例如空对象可能缺少 read_file.path，
M03 才实现工具专用参数校验。跨消息 ID 配对也尚未实现，不能用单消息验证冒充。

## 数据流与状态归属

`load_config → FakeProvider → complete(内部 Message 序列) → assistant Message`
`→ collect_demo_events → AgentEvent → model_dump_json → stdout`

Provider 的最小结构接口为异步 `complete(messages: Sequence[Message]) -> Message`。
供应商 SDK 只能用于未来适配器内部；Runtime 只需要这个接口和内部契约。
这使 Runtime 的停止或工具处理测试不必构造 SDK 响应对象。

本轮 fake 只拥有响应 deque；成功调用后长度从 2 到 1，再到 0。
空请求先拒绝，不消费响应；耗尽后持续抛 FakeProviderExhausted。
演示为两次独立请求，不回传结果，不自动继续推理，没有 Agent 循环。

后续 Runtime 应拥有运行中的消息历史与回合控制；会话持久化在 M11；
工具执行入口/调度器维护执行状态，调用 ID 用于关联结果。
Provider 不应成为这些状态的所有者。本轮演示中的固定 ID 和序号用于复现，
不具有生产环境的全局唯一性，AgentEvent 本身也不保证跨事件顺序。

## 依赖与取舍

- Python 3.11+；使用标准库 asyncio、tomllib，无配置框架和 UI 依赖。
- 运行依赖 Pydantic；开发依赖 pytest、Ruff、mypy；构建后端 Hatchling。
- uv.lock 锁定项目运行与开发依赖的解析版本；本次 Pydantic 2.14.1、pytest 9.1.1、
  Ruff 0.17.0、mypy 1.20.2。Python 解释器不由依赖锁锁定；
  隔离构建环境中的 Hatchling 及其依赖也不由这份项目锁完整固定。
- Provider 使用 Protocol 而非继承体系；fake 每实例独立，无网络、自动重试或共享全局脚本。
- 配置只有 fake/fake-m01；路径显式指定，错误直接上抛。不隐式读密钥或 .env。
- 先定义整个消息事件，不提前实现 M06 的 delta 与流式事件家族。

实现前核对的官方资料：
[Pydantic models](https://docs.pydantic.dev/latest/concepts/models/)、
[serialization](https://docs.pydantic.dev/latest/concepts/serialization/)、
[uv 锁定与同步](https://docs.astral.sh/uv/concepts/projects/sync/)、
[Ruff 配置](https://docs.astral.sh/ruff/configuration/)、
[pytest assertions](https://docs.pytest.org/en/stable/how-to/assert.html)、
[mypy 配置](https://mypy.readthedocs.io/en/stable/config_file.html)。
Pydantic 提供通用验证和序列化；本项目自己定义角色、载荷和 ID 的语义约束。

## 三个失败场景

| 场景 | 可控注入 | 实际验证 |
| --- | --- | --- |
| 非法契约 | user 带调用、重复 ID、分片 JSON、SDK 额外字段、非有限数 | ValidationError；不产生可供执行的 ToolCall |
| 无效配置 | 真实 provider、未知键、缺文件、坏 TOML | ValidationError / FileNotFoundError / TOMLDecodeError；无默认回退 |
| fake 耗尽 | 两次合法返回后第三次请求；空脚本 | FakeProviderExhausted；不循环复用旧调用 |

异常由调用方观察；pytest 保留失败类别，命令行配置错误会非零退出。
本轮未建立生产日志、错误事件或运行终态机制。

## 验收与边界

在仓库根目录按 README 的命令执行同步、35 个测试、Ruff、mypy 与演示。
首轮 30 个测试的原始输出保留于 `../evidence/M01-checks.txt`；
本轮复验见 `../evidence/M01-recheck.txt`；演示见 `../evidence/M01-demo.jsonl`。
契约测试覆盖完整消息与事件往返、状态序列化和故障边界。
两行 JSON 的第二行只有工具请求，工具执行次数为零（演示没有执行入口）。
这些证据只支持离线契约，不支持真实模型能力、协议兼容或后续 Runtime 正确性。

## 本轮补齐的验证（2026-10-12）

核对 ROADMAP 后确认 M01 功能已覆盖，未发现需要改动核心代码的缺项。
新增的五个测试把既有声明变成更明确的证据：

- `tests/test_boundaries.py` 从实际 contracts 源码解析静态导入，限制其依赖方向；
  这是静态回归检查，不声称防止任意动态导入。
- `tests/test_demo_process.py` 在临时目录启动真正的 Python 模块进程，解析 stdout 中的事件。
  目录没有 README.md，仍能返回请求，且目录文件集合不变；说明本演示不需要实际文件工具。
- 三种坏配置（未知 provider、缺文件、坏 TOML）均非零退出且不输出事件。
  不只断言 load_config 抛异常，还核对完整入口的可观察行为。

复验矩阵：Linux 上 Python 3.11.16、3.12.12、3.14.7 各 35 passed。
通过为每个版本指定临时 `UV_PROJECT_ENVIRONMENT` 隔离安装，使用同一个 uv.lock，
禁用自动下载 Python；仅使用已经安装的解释器，全部临时环境完成后自动清理。
测试并非在三个不同操作系统上运行。

包验证：`uv build --wheel` 生成 `dist/codepilot-0.1.0-py3-none-any.whl`；
用 `uv export --locked --no-dev --no-emit-project --format requirements-txt` 导出固定运行依赖，
在新的 Python 3.11 环境安装依赖和 wheel。仓库外用 `python -I -m codepilot.demo`
运行，导入位置为 site-packages，输出见 `../evidence/M01-wheel-demo.jsonl`。
这避免 editable 安装或工作目录掩盖遗漏包文件；dist 已被 Git 忽略。
未做 sdist 安装、Windows/macOS、Python 3.13 或真实 API 验证。

## 文件职责与分层原因

| 文件或目录 | 职责与设计原因 |
| --- | --- |
| pyproject.toml / uv.lock | 分别声明依赖与检查规则、固定项目依赖解析；安装与检查使用同一项目配置 |
| .gitignore / .env.example | 忽略环境、缓存、构建产物与本地配置；说明 M01 不需要密钥 |
| codepilot.example.toml / config.py | 给出可运行样例和显式配置入口；错误不静默回退 |
| src/codepilot/__init__.py | 标识可安装包；src 布局让仓库根目录不会直接成为包导入来源 |
| contracts/__init__.py / models.py | 导出公共类型、维护语义约束；供多个组件共享，避免 SDK 类型扩散 |
| providers/__init__.py / base.py / fake.py | 标识适配器包、声明最小接口、提供有限离线脚本；隔离模型实现与核心数据 |
| demo.py | 验收入口和事件序列化；目前规模适合单文件，不提前拆 UI 或 Runtime 框架 |
| tests/test_contracts.py / test_config.py / test_fake.py | 原有单元验证：数据约束、配置、响应消费与故障边界 |
| tests/test_boundaries.py / test_demo_process.py | 本轮新增：依赖方向和模块入口的进程级行为回归 |
| README.md | 最短安装、演示和检查入口 |
| docs/STATUS.md | 已通过、未运行、下一步及学习进度的事实记录 |
| docs/design/M01.md / docs/learning/M01.md | 分别保存机制取舍与独立练习，便于核对实现与学习目标 |
| docs/evidence/ | 保留原始检查输出与模拟轨迹，让完成声明可追溯 |

本轮只新增上述两个测试文件，更新 README、状态、设计与学习说明，保存复验日志和 wheel 轨迹。
核心实现与项目依赖未修改；没有新增 runtime/tools 等后续阶段目录。
