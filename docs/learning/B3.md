# B3：可靠恢复与长任务治理的阅读记录

状态：支持范围内实现与受限验收通过；学习待用户确认，不布置动手题。

## 先用一段话理解

这次补齐的是“连续工作后，退出、崩溃或升级还敢不敢继续”的基础。CodePilot 现在能备份和升级会话库，能解释上次卡在哪一步；发现写入是否完成不确定时，会保留文件、暂停并要求协调，不会把旧命令再跑一遍。摘要之外，控制器另外保存命令退出码、文件版本和来源编号，文件后来变化时会标记旧记录不再适用。你能查看上下文和摘要、撤回压缩；不同模型请求的用量与估算费用也有来源，旧备份不能用来重置额度。这些能力都进入原来的 codepilot 产品链，而不是另外写一个演示循环。

## 一次正常轨迹

用户输入修复任务 → Application 持有会话锁，检查工作区身份 → 新 run 保存任务修订和基线 → Provider 请求前保存唯一预算预留 → 完整工具调用进入权限/调度 → 工具结果记入事件，控制器保存退出码与工作区 stamp → 运行结束保存变更和可验证快照。

用户退出再 resume → 校验快照覆盖点及哈希，重放后续事实 → 核验工作区与资源 → 复用来源匹配的摘要 → 在最新用户请求之前补入有界控制器执行记录 → 创建新 run 继续。原来的工具不会因为恢复而再执行。

真实样本是两个模块的 Unicode 标签合并：`keys.py` 负责 casefold，`merge.py` 必须复用它完成去重、去空白和顺序保留。两协议分别 7 次修复请求，随后各一次严格摘要和一次新进程续问，共 18 次成功链请求；前面另有两次消息顺序失败，合计 20 次尝试。公开和隐藏测试由外部控制器运行，模型没有看到隐藏用例。

## 三个关键故障轨迹

1. **升级失败**：先生成完整备份 → DDL 与版本号同事务执行 → 注入 SQL 故障 → 事务回滚，原事件和 v1 版本保留。活跃会话不允许维护命令抢锁。
2. **写入后崩溃**：控制器已记 running 和资源 → Shell 写了文件 → 控制器真实退出 → 新进程拒绝直接 resume → 活跃资源未结束则拒绝协调 → 核验后补“结果未知”错误 → 新任务继续，文件不重复追加。
3. **摘要失真或撤回**：JSON/来源编号非法则不替换旧检查点；合法摘要也仅是候选。用户 reset 时归档检查点、暂停自动压缩，原文过大则停止；显式 compact 才恢复。模型说“测试通过”不能修改 `independent_verdict=not_run`。

## 当前目录与设计原因

```text
src/codepilot/
  ui/             CLI 和斜杠命令，只展示或调用服务
  app/            装配 Provider、Context、预算与执行生命周期
  sessions/       SQLite 事件/快照、迁移备份、事实与上下文维护
  context/        Prompt 视图、结构化候选摘要与来源检查
  providers/      协议适配、共享尝试预算、重试与能力价格来源
  runtime/        单次循环、停止及工具调用边界
  permissions/    审批与实际执行授权
  scheduler/      资源冲突与并发限制
  workspace/      Local/Rootless Docker/worktree 后端
scripts/          有显式 --live 开关的真实联合验收
tests/            确定性故障与真实子进程回归
docs/             状态、设计、阅读材料和 evidence
```

没有单独创建“恢复 Agent”，因为恢复不应再让模型猜测哪些旧工具要重跑；控制器从持久事实决定能否继续。没有增加逐个 Git 子命令包装器。快照可以加速消息视图重建，但重开仍须扫描并验证事件前缀，不能据此宣称任意大历史都能常数时间恢复。

## 三道理解题及答案

**1. 数据库版本升到 v2，为什么事件仍是 v1？迁移失败会留下半个新版本吗？**

数据库布局新增快照表，旧事件含义没有变化，两个版本应独立演进。迁移先备份，再显式事务执行 DDL 和 user_version；故障回滚主库，完整备份仍可读。未来未知版本拒绝猜测升级。

**2. 为什么 Shell 退出码为 0 仍标 independent_verdict=not_run？后来改文件会怎样？**

退出码只能证明那条命令在那个版本执行成功，不证明命令覆盖了用户所有需求，更不证明测试没有被修改。控制器保留来源和 stamp；文件变化后 `current=false`，历史执行仍存在，但不能当成新版本已验证。真实验收另外运行隐藏测试并核对保护文件。

**3. 为什么恢复旧备份之后还要协调，预算为什么也不能倒退？**

恢复数据库不会同时回滚工作区、外部服务或账户扣费；旧事件不再足以证明当前文件状态。恢复强制 needs_reconciliation，并保留较大累计请求/Token/估算费用和未知预留，避免把恢复操作变成重复调用或免费重置额度的入口。

## 保留的边界

数据库备份不包含工作区与输出原文；摘要来源校验不证明语义无损；费用只是有日期来源的估算。B2 网络秘密、硬磁盘配额、worktree+Docker Git 和安全撤销仍未完成。其他平台、其他模型和最大窗口极值没有本轮证据。B4 仍待后续开发。

## 2026-10-19：限容任务跨控制器恢复

B3 在此前已经实现长任务预算、压缩、双协议和持久恢复。本轮把后来加入的限容执行模式接入同一恢复链，不能把“仍有发布阻断”误写成“还没开始 B3”。B2 网络/秘密缺口保留，但断网恢复不依赖这些能力。

### 推荐阅读顺序

1. `ui/cli.py::build_parser/main/_handle_slash_command` → `app/operations.py::recover`：先看 `recover SESSION RUN [--apply]` 和 `/recover` 如何进入零模型维护，默认只预览，应用也不自动修改源目录。
2. `workspace/docker.py::_save_handoff/_save_checkpoint/start`：看 create 前保存随机名字与 backend_id、阶段/配额/根目录身份，以及先保存内容寻址归档、再提交 SHA 指针的顺序。创建请求超时属于未知，不重试 create，也不谎报 closed。
3. `workspace/recovery.py::load_handoff/verify_container/recover_workspace`：看 Rootless、名称/标签/镜像、私有 PID/网络/挂载限制的核验；活盘导出、已停止检查点退化和已恢复重复调用分别走哪条路。
4. `sessions/store.py::bounded_workspaces/reconcile/ensure_deletable`：恢复只结束资源不确定性；未知工具与费用仍保留，明确协调才允许新任务。未交付产物不能被 TTL/delete 静默删掉。
5. `tests/test_b3_bounded_recovery.py` → `test_b3_bounded_recovery_live.py`：先看确定性故障，再看真实杀控制器、创建结果未知、停止 tmpfs 后的数据丢失报告，区分模拟通道和真实 Docker。
6. `docs/evidence/B3-bounded-recovery-checks.json`、`B3-bounded-recovery-live.json`：最后核对正常轨迹、失败经过、真实模型续问，以及模型/工具/Runtime/独立判据四层结果。

正常轨迹：控制器保存 creating 绑定 → 容器创建并登记 → 导入并发布已知检查点 → Shell 写入后控制器被杀 → 新 CLI 持会话锁读取绑定 → 只读预览真实容器 → --apply 核验后停写、导出、保存产物、删除容器 → 会话仍 needs_reconciliation → 用户明确协调后未知调用补为错误而不重放 → 原 delivery 按源版本交付 → 新模型任务只读续问。重复恢复不把 applied 改回 retained。

目录职责保持不变：app 编排会话锁与状态；workspace 的 recovery.py 管产物与资源恢复，docker.py 管控制器绑定及容器生命周期；sessions 管唯一历史/预算与协调；ui 只提供入口；tests/evidence 分开保存模拟和真实结果。没有新增“恢复 Agent”或第二套数据库，也没有新增模型可调用的 Docker/Git wrapper。

三道理解题及答案：

1. **一次 docker inspect 查无容器，为什么 creating 阶段仍不能报告清理完成？** 创建可能已被 daemon 接受，客户端先超时或被杀，容器稍后才出现。创建前的随机名称和标签用于后续核验；在结果未知时保留绑定，只重试查询，不重发创建请求。
2. **为什么检查点需要内容寻址，不能只覆盖 bounded-latest.tar？** 覆盖归档后、提交新哈希前崩溃，会让旧指针也找不到旧内容。先写 SHA 命名归档，再保存指针，最后删除旧归档，提交前仍有旧检查点可用。latest 只是查看副本，不是提交依据。
3. **产物恢复成功后为什么还要协调，为什么不清空 pending 预算？** 已保存文件不代表旧工具返回了确定结果，也不代表服务端没有计费。恢复不重放旧命令、不自动交付、不自动标记任务成功；未知结果与费用保留，显式协调后才开启新任务。

学习仍待用户确认，没有动手题。tmpfs 消失后只能恢复已提交检查点，必须报告 data_loss_possible；旧版本没有可靠绑定时不能猜测恢复。
