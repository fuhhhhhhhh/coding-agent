## 三道理解题及答案

### 1. 为什么检查点不能替代消息历史？

摘要可能遗漏事实或模型产生错误概括；SQLite 中的消息和工具结果才是规范事实。检查点只是有来源、可替换的 Prompt 视图，损坏时不能伪造历史为空。

### 2. 为什么请求预算要先 reserve 再 settle？

并发请求如果等响应后才记账，会同时看到同一剩余额度而超发。先预留可以在网络副作用前阻断竞争，收到 usage 后再把估算或实际用量结算。

### 3. usage 缺失时为什么不释放额度？

请求可能已被服务端接受，客户端只是没有拿到计量。释放额度会允许无限重试并产生不可见费用，因此只能保守保留请求占用，等待用户明确新任务或协调。
