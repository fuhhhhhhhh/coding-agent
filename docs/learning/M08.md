# M08：理解资源调度而不是直接使用 gather

本阶段推荐阅读顺序：

1. `docs/design/M08.md`：先理解权限、调度和工具执行的层次。
2. `scheduler/models.py::ExecutionPlan`：看一次调度决策保存哪些最小数据。
3. `scheduler/executor.py::ScheduledExecutor.plan`：看实际路径如何变成资源键。
4. `scheduler/executor.py::_conflicts`：理解读取共享、同路径写冲突和独占规则。
5. `scheduler/executor.py::_acquire`：看容量、活动调用和先到等待项如何共同决定启动。
6. `runtime/loop.py::Runner._execute_calls`：看何时允许并发，以及结果为什么仍按原调用顺序回传。
7. `permissions/executor.py::PermissionedExecutor.supports_parallel`：看权限层如何透传安全并发能力。
8. `tests/test_scheduler.py`：对照并发、串行、取消、进程清理和脱敏场景。
9. `m08_demo.py`：查看可测的并行与串行耗时。

一次双读取轨迹是：完整组装两个调用 → 分别通过权限 → 两项入队 → 在容量二且资源无冲突时同时调度 → 较快调用先产生
`tool_finished` → Runner 按原调用顺序写入两条工具消息。完成顺序用于观察真实性，消息顺序用于保持协议配对稳定。

理解题：

1. 为什么 Runner 不能看到多个 ToolCall 就直接对所有执行器使用 `asyncio.gather`？
2. 为什么 glob/search 的工作区读取必须与任意路径写入冲突，而两个 `read_file` 可以同时运行？
3. 为什么 Trace 可以在内存保存 `path:a.py`，落盘时却只能保存 `path:<redacted>`？
