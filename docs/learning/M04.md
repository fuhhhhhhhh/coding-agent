# M04：理解修改保护和进程清理

按用户要求不设置动手题。本阶段重点是两个无法由“调用成功”直接证明的故障边界。

## 必读入口

1. `tools/file_common.py::_check_expected_hash`：版本前置条件如何阻止覆盖外部修改。
2. `tools/file_common.py::_atomic_write`：临时文件、刷新和替换的关系。
3. `tools/edit_file.py::EditFileTool.run`：二次哈希检查和 diff 生成。
4. `tools/shell.py::_stop_process_group`：终止、升级信号和 wait 的顺序。
5. `tests/test_file_tools.py` 与 `tests/test_shell_tool.py` 中的冲突和子进程测试。

## 一次文件故障轨迹

`docs/evidence/M04-hash-conflict.jsonl` 展示：读取 `value.txt` 得到哈希后，外部把内容改成
`external`；Agent 带着旧哈希请求编辑，结果为 `conflict`，文件仍保留外部内容。

`docs/evidence/M04-atomic-edit.jsonl` 展示成功编辑，结果中同时有 `edited` 摘要和 unified diff。

## 一次 Shell 故障轨迹

`docs/evidence/M04-shell-timeout.jsonl` 展示 Shell 启动等待命令后超时。工具返回 `tool_timeout`，
当前进程退出；单元测试另外启动子进程并确认它不再处于运行状态。

## 理解题

1. 为什么只在写入完成后计算哈希不能防止“读后被改、写时覆盖”的问题？
2. 同目录临时文件和 `os.replace` 分别解决了什么问题，又为什么不能解决跨文件的事务一致性？
3. 为什么终止一个 Shell 进程不等于终止它启动的所有进程，进程组策略在 Windows 上还需要什么真实验证？
