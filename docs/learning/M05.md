# M05：理解权限决策和审批边界

按用户要求不设置动手题。本阶段重点是权限审批和系统隔离之间的边界。

## 必读入口

1. `permissions/policy.py::PermissionEngine.decide`：规则匹配和拒绝优先。
2. `permissions/executor.py::PermissionedExecutor.execute`：权限层如何包住现有工具执行器。
3. `permissions/approval.py::ConsoleApproval`：为什么 CLI 审批只负责回答是否批准。
4. `permissions/models.py::ApprovalRequest` 与 `PermissionAudit`：参数绑定和审计字段。
5. `tests/test_permissions.py`：拒绝、取消、通过和容器模式故障路径。

## 一次审批轨迹

`docs/evidence/M05-checks.txt` 的演示输出包含四个场景：

1. 只读策略拒绝 `write_file`，目标文件不存在。
2. 逐次审批返回 false，`write_file` 没有执行。
3. 审批返回 true，随后才创建文件。
4. 容器模式尚未实现，即使请求读取也明确拒绝。

每个场景的审计记录都带有决策和结果。审批看到的是完整工具参数，而不是只有工具名；参数改变会生成新的请求。

## 理解题

1. 为什么 `PermissionedExecutor` 必须放在 ToolRegistry 前面，而不是工具执行后再记录权限？
2. “拒绝优先”解决了什么配置错误？如果 allow 规则先匹配就立即返回，会出现什么风险？
3. 为什么 `container_mode_not_implemented` 必须是拒绝，而不能先允许工具、以后再补容器？
