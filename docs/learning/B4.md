# B4 阅读说明：扩展如何共用同一条执行链

可以把这轮理解成：主助手现在可以按需查技能说明、把定位工作交给一个只能读文件的小助手、
把长命令放到后台，并调用用户明确配置的本地外部工具。但它们共用原来的审批、预算、日志和清理规则，
不会因为换了“扩展”或“子助手”的名字就获得更大权限。资料不是授权，模型报告也不是验收结果。

## 推荐阅读顺序

1. `src/codepilot/app/service.py` 的 `_execute`：先看统一产品如何装配 Router、ManagedExecutor、
   子 Runner 与退出回调。抓住“只有一套产品入口和资源所有者”。
2. `src/codepilot/extensions/models.py` 与 `tasks/manager.py`：理解可信配置、任务 ID、parent_run/
   parent_call、状态、输出游标和 SQLite 事实。持久任务记录不等于可以自动恢复任务进程。
3. `src/codepilot/extensions/router.py` 的 start/delegate/_mcp/hook：从一个工具请求跟到实际后端，
   看为什么 Docker 不退回宿主、Hook 不改参数、MCP 每次调用重新核验目录。
4. `src/codepilot/extensions/executor.py` 与 `scheduler/executor.py`：看共享实际操作预算、父权限交集、
   延迟释放后台租约，以及控制请求为何可越过队列；再看只读 delegate 为什么不持有外层租约。
5. `src/codepilot/tasks/children.py` 的 ChildBudget/run_child 与 `tasks/terminal.py`：前者说明子请求
   如何消耗同一个总账本，后者说明 PTY 的输入、输出捕获、取消和第二层终端回显。
6. `tests/test_b4.py`、`tests/test_b4_docker_live.py`，再读 `docs/evidence/B4-live-first-failure.json`
   与 `B4-live.json`：先看重要故障断言，再把真实失败与修复后的模型/工具/Runtime/独立结果分开读。

## 一次执行轨迹

用户发修复任务 → Prompt 只列出 Skill 元数据 → load_skill 校验哈希并加载正文 → 主助手 delegate
只读定位 → TaskManager 先保存任务再创建子 Runner → 子请求在父账本预留、读取工具逐次审批调度 →
主助手 task_status 得到带来源的模型报告 → 主助手修改前执行受控 Hook → 原工具单独授权执行 →
task_start 后台测试，返回 ID 后仍持有写租约 → task_status 查实际退出和原文 → MCP list/call 分别授权 →
主 Runtime 结束 → 取消尚未结束的子工作并关闭后端 → 控制器再独立运行测试、检查保护文件与资源。

真实测试的具体顺序和成功程度以 evidence 为准；这条轨迹解释机制，不替模型补造未发生的步骤。

## 三道理解题与答案

**1. 后台测试返回 job ID，为什么不能立刻释放写租约？**

答案：返回 ID 只表示控制器接管了任务，命令仍可能修改代码或测试产物。立即释放会允许另一个写入
同时发生。租约延迟到实际任务结束；读取可以继续但不保证快照，取消控制必须始终可到达。

**2. 为什么只读子代理不能一直持有一个外层读租约？它不是更安全吗？**

答案：子代理还会逐次申请读工具租约。父 Hook/进程可能排队等待外层租约，而公平队列又阻止子读取
越过它，形成循环等待。外层只负责创建受限任务，实际读取各自获取/释放租约，才能避免依赖环。

**3. 子代理用完自己的次数后，能否重新委派得到一份新的总 Token 预算？**

答案：不能。它没有 delegate/Shell/写工具；ChildBudget 的 consume 和 settle 都交给父对象，父总次数、
Token 账本和持久会话次数共同生效。子报告只带来源和 not_run 判定，父助手还需要实际测试与独立验收。

实现和阅读材料由 AI 交付；用户掌握情况待确认，没有将阅读说明或测试数量计为用户独立开发贡献。
