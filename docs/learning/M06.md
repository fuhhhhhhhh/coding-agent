# M06：理解独立验证和反馈纠错

本阶段推荐阅读顺序：

1. `docs/design/M06.md`：先看 Harness 的边界和状态分类。
2. `src/codepilot/evals/models.py`：理解 `TaskSpec`、`VerificationResult`、`AttemptRecord` 和 `TrialResult`。
3. `src/codepilot/evals/verifier.py::IndependentVerifier.verify`：看验证器进程如何区分通过、失败、错误和超时。
4. `src/codepilot/evals/harness.py::LocalHarness.run`：追踪一次尝试如何得到反馈并决定是否重试。
5. `src/codepilot/evals/harness.py::LocalHarness.run_batch`：看批量任务如何保证每项从干净副本开始。
6. `tests/test_evals.py`：对照正常纠错、空补丁、验证器错误和验证器超时。
7. `src/codepilot/m06_demo.py`：运行一次最短的失败到成功轨迹。

一次完整轨迹是：复制源目录 → Runner 执行候选 → 开发测试反馈 → 工作区外独立验证 → 成功或带分类重试。
`docs/evidence/M06-checks.txt` 保存验收命令和演示结果。

理解题：

1. 为什么模型回复 `done` 只能结束一次候选，不能直接把任务标记为成功？
2. 为什么独立验证器的代码和参考答案不能放进 Agent 工作区？
3. 验证器超时为什么分类为 `timeout`，而不是继续把同一份反馈交给模型重试？
