# CodePilot 产品化路线与成熟度门槛

版本日期：2026-10-19（UTC）；阶段门槛保持，实际通过范围以 STATUS 和 evidence 为准。

## 1. 目标、事实与规划权威

目标是让用户在真实仓库中持续完成“理解需求 → 定位 → 修改 → 测试 → 纠错 → 审查 → 继续对话”，并在拒绝、取消、断流、崩溃时保护已有劳动。以当前目录、简单工具、原生 CLI、明确权限和可诊断错误作为产品原则，不推测 Claude Code 的内部实现，也不把功能数量当成成熟度。

执行顺序以本文件为准，当前进度看 `docs/STATUS.md`，具体增量的设计、学习和证据分别放在 `docs/design`、`docs/learning`、`docs/evidence`。`ROADMAP.md` 顶部同步当前大阶段顺序，原续接规划和旧 M01—M18 保留为历史参考，不能仅凭旧 M 编号推进；M01—M10 历史成果不重新验收为“未完成”。用户已允许 ROADMAP 正常修改、提交和推送，无需特殊排除。

每项能力分别记录：机制实现、链路集成、真实验收、产品就绪。一个组件有真实证据，不代表整阶段或整产品就绪；已完成阶段以后发现的缺口在新增量修复，保留原证据适用版本。

## 2. 阶段顺序、交付单位与完成判据

P1/P2 保留真实验收记录。后续按 **B1 → B2 → B3 → B4 → B5 五个大阶段**组织开发与交付，每轮完成一个大阶段的完整产品链。当前 B1 已通过 Linux Local、Rootless Docker 和受限真实模型验收，B2 基础受控执行增量已验证；B3 已通过明确支持范围的受限验收，B4 已通过明确支持范围的受限验收，B5 的终端/评测/安装链已受限验收，成熟发布仍被 B2 遗留项阻断。P3—P8 及其 25 个细项保留为技术范围与验收索引，不再作为 25 次独立交付，也不要求按 P 编号串行。

用户已明确要求一次开发一大点。内部可以分步骤实现、测试和建立多个清楚的提交，但不在每个细项后结束工作或重新请求继续；只有整个阶段达到门槛才报告完成。真实阻碍必须说明实际缺失，不能将已完成部分冒充整阶段完成。

| 大阶段 | 一次交付的产品行为 | 对应技术清单与范围 |
| --- | --- | --- |
| **B1 可靠执行与持久会话基础（受限真实验收通过）** | 输出可找回、任务可连续追问、退出后历史仍在、异常重开明确协调 | 取消清理修复；P3.1；P3.3 的输出/task/session 配额和最小资源清单；P5.1/P5.2 的基础版本；P5.3 的安全重开检查。具体契约与联合验收见 `docs/design/B1.md` |
| **B2 受控工作区与安全执行（安全交付已受限验收，整体待续）** | 普通只读检查低摩擦，危险操作解释实际副作用；修改与撤销保护用户已有劳动，Docker 边界可验证；交互命令可发现且不消耗模型请求 | P3.2；P3.3 剩余存储边界；P3.4—P3.6；P5.4。网络模式需真实强制边界，不支持时保持明确拒绝 |
| **B3 长任务、恢复与 Provider 可靠性（受限验收通过）** | 多次压缩仍保留证据，检查点可跨进程读取，崩溃后保守继续，所有请求受共享预算约束 | P4 全部、P5.2/P5.3 的快照/迁移/完整协调深化、P6 全部；在 B1 已有存储上演进，不重建第二套会话系统 |
| **B4 扩展与后台协作（受限验收通过）** | Skills/Hooks/MCP 与后台任务、受限子 Agent 共用产品治理链 | P7 当前支持本地无状态 stdio、受控 Hook、按需 Skill、后台/PTY 与只读子任务；远程/有状态 MCP、写 Agent/团队另行演进，不冒充已通过 |
| **B5 真实任务评测与发布（交付链受限验收，成熟发布阻断）** | 干净安装后完成真实仓库任务，质量、成本、失败和支持范围可核对 | P8 全部门槛与最终发布；P8 的交互、固定任务回归和安装检查同时贯穿 B1—B4 |

本轮 B3 联合通过范围（2026-10-19）：逐尝试持久预算、明确拒绝的有界重试、检查点来源匹配及跨进程滚动复用、主动 `/compact`、双协议真实 CSV 修复与独立测试。本轮继续补齐数据库 v2 备份/迁移/恢复、快照核验、三处真实控制器崩溃矩阵、版本化控制器事实、上下文审查撤回与精确官方组合的费用能力表，并通过确定性/Rootless Docker/双协议真实任务/干净安装联合验收。B3 为支持范围内受限通过；B4 的当前受限范围见下文及 B4 设计/evidence。详见 `docs/evidence/B3-live-repositories.json` 与 `docs/evidence/B3-finish-checks.txt`。

B1 基础持久化提前，完整崩溃恢复不等同于读回消息。重开已结束且环境核验通过的会话可以创建新 run；遇 running/unknown、未配对调用或副作用不明时进入 needs_reconciliation，不自动执行旧工具。B3 才深化完整崩溃协调流程。

此前取消清理不稳定已在 B1 用屏障稳定复现并修复：gather 传播取消后，Runtime 二次取消打断活动任务清理。B1 已联合交付输出与持久会话，原失败记录保留，详见 docs/design/B1.md 和 evidence/B1-*。

交互、评测、故障诊断、安全边界在每阶段验收。实际使用发现丢数据或越权缺陷时，先在当前阶段处理；对受影响阶段及证据明确记录，不能用拆分计划代替完整交付。

阶段完成需要以下证据共同成立：

1. 正常流程进入现有 `CodePilotApplication` 和 `Runner`，不是另写 demo 循环。
2. 本阶段每个增量的三个重要故障均有确定性断言，副作用和清理结果由控制器检查。
3. 适用时运行 Rootless Docker；变更涉及模型协议/上下文决策时做受限低成本真实模型验收。
4. 区分 `model_claim`、`tool_result`、`runtime_outcome`、`independent_verdict`。无独立判据时 verdict 为 `not_run/unknown`，不能默认为 passed。
5. 更新状态、设计、学习、证据；提交只含已授权范围，禁止秘密进入提交；ROADMAP 的用户已有修改已获明确授权纳入本轮。

`completed` 只表示 Runtime 正常结束。测试命令成功不自动证明需求全满足；任务失败、验证器不可用、预算耗尽、环境失败必须分开报告。

## 3. 内部契约与状态所有权

以下为后续设计的最小字段要求，**不是已存在的 Python 类或必须一次建齐的模型**。只在相应增量落地，并优先扩展现有 `ToolResult`、`CommandResult`、`ProductRunResult` 等契约。

| 契约 | 必要信息 | 唯一所有者 |
| --- | --- | --- |
| OutputCapture / Artifact | run/call/stream、字节偏移、已观测/已保存字节、摘要哈希、complete/partial/quota_exceeded、截断原因 | 执行后端生产，控制器私有存储保管；模型只能按 ID 有界读取 |
| Action / ApprovalGrant | 标准化参数摘要、cwd、后端与工作区身份、资源、环境变量名、网络/秘密能力、有效期、策略版本 | 权限层生成及判定，执行器复核；模型声明不构成授权 |
| RequestBudgetReport | 消息/Schema/包装开销、输出预留、估算来源及误差、剩余总预算 | Provider 提供计量方法；Context 决定装配；共享账本记账 |
| WorkingState / Checkpoint | 用户目标与修订、规则来源、待办、文件版本、测试证据、未决风险、覆盖事件范围 | 控制器保留事实；模型只提出有来源的摘要候选 |
| SessionEvent / Snapshot | schema_version、序号、关联 ID、事件类别、持久化位置和快照覆盖点 | 会话存储；Trace 是脱敏观测视图，不自动充当可恢复历史 |
| ChangeRecord / Verification | 修改前后哈希、用户已有差异、来源 call、验证 argv/环境/退出码/Artifact、判定适用版本 | 控制器；避免模型把“计划运行测试”写成“测试通过” |
| TaskRecord | 父子任务、状态、预算预留、权限上限、执行资源、产物和协调原因 | 任务管理；Runner 管单次执行，不自行拥有所有持久资源 |

默认脱敏 Trace 不保存正文；恢复需要的消息/输出进入独立、限权、可删除的私有会话存储，明确保留策略。原始输出也可能包含秘密：控制器私有原文不得自动回灌模型或导出日志；给模型/终端的视图经过有界过滤，不能声称任意编码秘密都能检测。

## 4. P3：受控执行面、工具与直接工作区保护

以下 P3—P8 是技术清单，按第 2 节映射纳入 B1—B5 联合交付，不按每个小节单独结束工作。

### P3.1 截断前输出捕获（纳入 B1 联合交付）

- 范围：沿现有 Shell、Local 固定 argv 与 Docker 命令路径接入 controller-owned OutputSink；保持工具简单。stdout/stderr 独立排空，记录每路顺序，不虚构两条管道的精确全局顺序。
- 契约：启动前分配 capture ID，分块追加字节，结束时提交可读取引用、统计与完整性；预览截断不丢掉已保存中段。Docker 的 worker/控制器传输也须分块，不能先在容器内裁剪再声称完整捕获。
- 生命周期：按 call 创建，取消/超时提交 partial，写入失败停止当前捕获和活动命令，收尾失败不得掩盖原始故障。引用由 B1 会话存储管理，在明确保留期内跨 run 可读；退出 run 不删除会话仍引用的正文，过期或删除后返回明确缺失结果。
- 正常验收：同一 CLI 任务输出交错的两路合成日志，中段包含唯一标记；模型工具可按 ID 有界读取/检索。控制器核对每路哈希、字节数和引用状态，测量控制器及 worker 峰值内存。
- 故障：超过 100 MiB 的交错输出仍内存有界；磁盘写入失败不能发布 complete；取消时保留可解释 partial 且无活动后代。UTF-8 跨块、不换行长行和二进制输出也不损坏原始字节。
- 退出门槛：Local 与真实 Rootless Docker 都走统一链。配额先给单命令硬上限；不把它写成任务 bind mount 的磁盘硬隔离。

### P3.2 Action、仓库信任与审批复核

- 范围：沿现有权限执行器规范化 Action，不新建第二条执行链；展示实际 cwd、后端、影响范围和授权来源。
- 交互体验：内置只读工具和已严格识别的查询 Action 可直接执行；仅由安全查询组成的 `&&` 组合可自动执行，其他 Shell 复合语法、网络、秘密、写入和未知命令仍需审批。TTY 提供可发现的斜杠命令入口，非 TTY 保持稳定文本协议。
- 可信用户配置设权限上限；项目配置只能收紧。来自未信任仓库的配置不能静默切换 Provider URL、凭据来源、执行后端、Hook、网络或自动批准规则。仓库规则可以指导编码，不能覆盖用户安全策略。
- 审批绑定完整 Action 摘要、session、有效期及策略版本；执行前再次核对。Shell 字符串无法可靠推导全部影响，归为保守 process 能力；未知命令不能因关键词匹配自动获得“只读”权限。
- 正常验收：同一 CLI 中文件只读允许、修改要求批准、Shell 以实际参数批准；非交互无审批通道时明确拒绝或采用显式预授权。
- 故障：批准后参数/cwd/后端改变须重批；项目配置企图扩大权限在副作用前拒绝；审批取消/过期后无工具启动。另覆盖符号链接路径替换与策略更新。
- 退出门槛：审计能解释 allow/deny/ask；会话授权只在精确定义范围复用。Local 上获批的任意 Shell 仍可访问宿主，不承诺靠路径规则完成沙箱化。

### P3.3 配额、资源清单和存储边界

- 范围：单输出、单调用、task/session 的字节和时限；有界队列及背压；最小资源清单记录 UID、ID、启动身份、创建/过期时间与状态。
- 区分三种限制：输出捕获硬上限、容器可写层限制、bind 工作区存储限制。文件增长扫描只是检测，不是硬配额。硬配额依赖受支持文件系统/存储驱动，启动时探测；请求硬限制但后端不支持则拒绝该模式。
- 显式受限存储模式可使用容量受限任务盘或副本，必须说明与默认直写语义的差别、同步冲突和交付方式，不能静默切换目录。
- 正常验收：资源额度在启动前预留，结束释放，残留清单可只读诊断；容器镜像记录固定 ID、来源与更新路径。
- 故障：多个调用竞争额度不超发；命令绕开输出直接写大文件时说明实际磁盘边界；控制器被杀后能发现归属正确的遗留资源。清理拒绝未知 owner、PID 复用或不匹配容器。
- 退出门槛：此技术项只发现/安全清理确定归属资源；跨崩溃状态协调由 B1 提供保守检查、B3 深化完整恢复。禁止修改、重启公共 Docker。

### P3.4 网络、秘密与依赖安装

- 范围：保留 Docker 默认断网；按任务申请联网能力和短期秘密引用，批准的是网络及凭据作用域，不是把 API key 放入模型参数。
- 契约：秘密仅由控制器注入获批进程，命名引用与值分离；最小环境白名单，关闭无意继承。Provider 密钥不进入工作区执行环境。网络若声称域名限制，须由真实代理/防火墙执行，不能仅审查命令字符串。
- 明确 Git SSH/HTTPS、包管理器、重定向/DNS、子进程及安装脚本边界；依赖优先锁定版本与预置镜像，安装脚本按 process 副作用审批，不自动信任。
- 正常验收：受控测试服务及临时裸远端完成获批联网操作；仅该任务可用，退出后凭据不残留在文件、配置、日志和进程中。
- 故障：未批准目的地拒绝；重定向或子进程绕过不能拓宽授权；合成秘密被回显时模型视图与 Trace 不泄露。另测网络中断和凭据失效，禁止盲目重放 push。
- 退出门槛：实际 Rootless 环境支持才开放相应网络模式；做不到时保留断网并写明阻碍，不用开全网冒充细粒度控制。

### P3.5 读、搜、改成为真实仓库工具

- 范围：read_file 行范围/分页/总行数及版本；search 的文件过滤、忽略规则、上下文行和显式截断；复用 rg 或现有实现，不提前建向量库/LSP 平台。
- 编辑记录读取时哈希和目标版本；生产编辑路径要求有效前置条件，旧接口兼容策略明确。支持一批文件修改的预检查和变更清单，但不承诺跨文件原子事务。
- 非 Git/脏目录记录与任务相关的初始版本；当前用户修改不因重试、格式化、清理而丢失。回滚只处理本任务拥有且仍匹配预期版本的改动，不执行无条件 reset/clean。
- 正常验收：大型仓库定位正确行区间，跨文件修改并根据真实失败日志修复；控制器验证用户预先存在的差异和未跟踪文件保留。
- 故障：读取后外部修改则编辑冲突；零/多处匹配不写入；两文件中第二个失败时列出首个已写文件。另测 CRLF、非 UTF-8、二进制、删除/重命名和单行巨大文件。
- 退出门槛：报告扫描/跳过/截断范围，不能把“没搜到”说成“仓库不存在”；结构检索在测到文本定位瓶颈后单独增加。

### P3.6 显式 worktree 与 Docker 组合边界

- 先选择可验证方案：在容器内创建独立完整仓库副本，或只暴露任务所需且受控的 Git 元数据。禁止为方便挂载宿主全部仓库管理目录或凭据。
- 设计源 commit、容器工作区、交付 patch 和清理归属关系；直写模式仍是默认，不要求用户手动搬运普通任务结果。
- 正常验收：显式 worktree + Rootless Docker 中原生 status/log/commit 可用，二进制补丁在固定起点重放并独立测试。
- 故障：源 commit 消失/元数据不可读时副作用前停止；错误容器路径不回退宿主执行；清理遇未交付修改拒绝删除。
- 如此增量未完成，组合保持明确的“不支持容器内 Git”能力状态，不能把已有文件编辑证据算作 Git 兼容通过。

## 5. P4：有界上下文与可信工作状态

### P4.1 完整请求预算

- Provider 边界计量消息、工具 Schema、协议包装、输出预留和误差余量；沿用当前配置而非先接新协议。精确 tokenizer 不可用时明确估算来源及保守余量。
- Context 根据报告决定发送、缩减可选内容、压缩或停止；摘要请求本身也受输入/输出/请求次数限制，全部计入共享预算。
- 正常验收：同任务在小窗口自动治理、在大窗口不多余压缩；预算报告能解释每项开销。
- 故障：短正文配巨型 Schema、单条用户消息超限、tokenizer 失效三者都不偷偷发送已知超限请求；缺失 usage 保持 unknown。

### P4.2 滚动检查点与结构化事实

- 摘要输入限定为“旧检查点 + 新增完整回合”，持久历史不是每次全量重算；控制器维护目标、规则、已修改版本和测试记录，模型输出严格结构化候选摘要。
- 检查点带覆盖范围/来源 ID/版本，校验成功才原子替换旧值；用户新约束按修订号保留，仓库文本不自动升格为系统权限。
- 正常验收：至少百回合固定历史、三次压缩，摘要输入和内存增长可解释；关键目标、未完成项和失败证据仍能定位原事件。
- 故障：摘要超时保留旧检查点；非法 JSON/伪造来源拒绝替换；调用和结果跨边界时以完整回合处理。控制器不能仅靠模型声称保证语义完全无损，需固定质量任务检验。

### P4.3 来源边界与用户控制

- 区分用户请求、受信任策略、仓库规则、代码、工具输出、扩展文本；后几者作为任务数据读取，不携带授权能力。控制器保护关键约束，不能把所有仓库正文塞成高权限 system 指令。
- 提供可解释的上下文占用、当前摘要和 `/compact`；每项命令仍调用产品服务。压缩撤回仅改变 prompt 视图，不回滚文件或重放工具。
- 正常验收：长任务经“搜索→编辑→失败测试→修复→独立验证”后继续回答证据问题；展示摘要成本与遗漏风险。
- 故障：日志含伪造系统指令不改变权限；目标被后来用户修改时旧摘要不覆盖新目标；Artifact 缺失清晰降级或停止。提示注入回归证明具体边界，不宣称彻底免疫。

## 6. P5：持续会话、持久化与保守恢复

### P5.1 真正的多轮会话

- 优先解决日常可用性：提示符中的“继续修这个错误”能看到上轮规范历史、WorkingState 和仍有效 Artifact。每个任务独立 run，session 持有共享预算与历史，Runner 仍可单次使用。
- 定义新任务/续问/新会话边界、工作区身份、退出保留策略；不靠猜测“同一 session ID”证明已有记忆。
- 正常验收：第一轮定位，第二轮修改，第三轮追问测试结果；无重复读全仓库且引用可访问。
- 故障：跨目录不能静默沿用旧仓库上下文；上一任务失败后事实仍保留但不假定通过；用户文件外部变化导致旧版本事实失效。B1 默认持久保存且支持重开；若提供显式临时会话模式，退出明确告知不可恢复。

### P5.2 私有存储、事件与迁移

- 追加版本化 SessionEvent 保存事实，SQLite 管索引、状态、归属与快照；脱敏 Trace 不承担正文恢复。持久层限制权限、配额、TTL，提供导出脱敏和删除入口。
- 明确写入顺序：副作用前持久化意图，工具开始/结果及预算变化追加事件，快照标注最后可靠序号；日志与数据库不假定跨介质原子提交，索引可重建。
- 单会话写锁或租约防两个进程同时恢复；锁持有人和过期判定可诊断。正文缺失/删除不制造可用引用。
- 正常验收：退出再启动重建历史/检查点/Artifact，Schema 升级前可备份，索引可从日志重建。
- 故障：SQLite 写失败、JSONL 尾部半条、快照与事件偏移不一致；已确认副作用不能因日志缺口自动重放。恢复所需正文不可用则明确停止。

### P5.3 崩溃协调与 resume

- 状态区分 planned/running/succeeded/failed/cancelled/unknown；副作用不明进入 needs_reconciliation。会话状态与单 run 终态分开；恢复创建新 run，不复活旧 cancelled run。
- `resume` 先核对工作区、资源、预算和权限，再装配 prompt；审批默认不跨崩溃继承。只读也须重新核对路径和环境，不因“只读”保证结果不变。
- 对三处分别注入真实控制器退出：模型请求前、文件/进程副作用中、工具完成但结果未持久化。核对实际文件/Git/进程，而非仅看事件。
- 正常验收：能解释哪些步骤已完成、哪些未知、如何人工确认后继续；清理只处理确定拥有的资源。
- 故障：不确定 commit/push 不能重放；容器已消失或 PID 复用不误杀其他任务；两个 resume 竞争只有一个写入者。用户取消后排队任务不能恢复启动。

### P5.4 变更归属、审查与安全撤销

- 直接工作区维护初始用户差异、本任务修改及当前版本；提供变更预览、验证记录和冲突提示。非 Git 目录也能审查已记录文件变化。
- 单文件/批次撤销要求当前内容仍匹配本任务修改后版本，检测用户后来编辑；rename/delete/mode/binary 明确支持范围。
- 显式 worktree 导出后自动应用仅在明确请求、目标前置版本匹配、先检查再操作时启用；冲突保留交付物，不默认合并。
- 正常验收：用户脏目录中完成任务后，仅撤销该任务可确认拥有的修改；原用户变更保留。
- 故障：用户在任务后又修改时拒绝盲撤销；目标分支漂移时交付冲突；恢复时补丁/文件哈希不匹配则协调。没有安全前置条件时宁可不给一键撤销。

## 7. P6：Provider 可靠性、能力协商与全局预算

### P6.1 安全错误分类与有界尝试

- 错误分认证/余额、限流、连接、请求总超时、服务端、协议、上下文/输出限额，展示安全诊断和建议，不输出 SDK 原文。
- 每次网络尝试先扣共享请求额度；退避计入总时限；尊重合法 Retry-After，并设置最大尝试/等待值与可取消等待。
- 保留当前关闭 SDK 自动重试的行为。请求是否被接受未知时默认不自动重发；流已消费尤其已生成工具调用时不可拼接第二次响应。支持幂等键的协议也需验证实际支持范围。
- 正常验收：可证明未发送的连接失败或明确允许重试的拒绝响应，有限重试后成功；所有 attempt 可追踪。
- 故障：429 超长 Retry-After 不无限等；服务端已接收但客户端超时进入不确定结论；重试等待时取消立即结束。重试耗尽不触发工具或生成额外终态。

### P6.2 能力和费用账本

- 能力表按 provider endpoint/model/protocol 组合维护：工具、并行调用、流、usage、上下文、最大输出、推理字段和计量来源；先校验再启动任务。
- 所有主请求、摘要、纠错、后台和子任务共享请求/Token/时间/估算费用总额；预留再结算，未知 usage 明示，不能按零释放出无限预算。
- 价格带来源日期；价格未知时只承诺请求/Token 上限，不承诺账户费用硬封顶。模型切换重新核验预算、能力、上下文和工具历史。
- 正常验收：主请求与摘要同时接近额度时不超发，报告估算与实际分离。
- 故障：usage 缺失、服务端超报用量、并发预留竞争均产生可解释预算结果；配置最大输出超过能力在请求前拒绝。

### P6.3 第二协议与组合兼容矩阵

- 先稳住当前 Chat Completions；再选择一种真正不同的协议，通过独立适配器进入同一内部契约，避免堆供应商特判进 Runner。
- 矩阵记录具体 endpoint/model/date 与文本、工具、并行、断流、usage、取消测试，不把网关故障概括为模型无工具能力。
- 正常验收：两个协议各在同一 CLI 完成读、写、Shell、失败反馈；确定性套件先行，真实调用优先便宜模型并硬限制请求数。
- 故障：重复/冲突分片、不完整参数/错误 finish、空流/缺失 usage 都有明确结果；完成契约前工具零执行。

## 8. P7：扩展、后台任务与受限协作

### P7.1 仓库规则与 Skills

- 规则按目录作用域和来源加载，给出冲突优先级和大小限制；高权限策略仍来自用户。Skills 发现仅注入名称/描述，正文按需加载，来源与版本可审查。
- Skill 是任务指引，不自动授予 Shell/网络/秘密。项目首次信任和更改后复核共用 P3 信任机制。
- 正常验收：真实任务按需加载一个 Skill 并在统一链完成；禁用后核心仍能执行。
- 故障：Skill 要求越权被拒；路径/符号链接逃逸拒绝；正文巨大或冲突规则给出有界可解释结果。

### P7.2 Hooks

- 定义触发阶段、严格输入输出、超时、失败策略、后端和重入边界；每次执行归属 task/call，仍受调度、权限、输出及总预算约束。
- 能改变工具参数的 Hook 必须在最终审批前完成；审批后改变参数必须重新授权。禁止 Hook 悄悄修改已验收补丁或在终态后继续运行。
- 正常验收：格式化/测试 Hook 影响可见，关闭 Hook 不破坏原任务链。
- 故障：卡死可取消；非法输出不直接写入核心状态；递归触发受限。项目恶意 Hook 默认不执行。

### P7.3 MCP

- 官方 SDK 只留适配边界，工具命名空间、Schema 版本和能力快照稳定；与本地工具共用校验、权限、调度、输出、Trace、恢复。
- stdio 子进程、HTTP 服务的网络/凭据各按 Action 管理；工具描述不具有策略权限；列举工具也计入时间与容量预算。
- 正常验收：一个真实本地 MCP 服务完成任务；禁用或断开后其余工具可继续。
- 故障：同名/Schema 突变不误调用；断开后未知副作用不重放；恶意描述/超大结果不绕过权限或预算。

### P7.4 后台任务与交互进程

- 先做后台任务状态和日志游标：queued/running/waiting/succeeded/failed/cancelled/unknown，前台退出时明确终止或移交托管，不能留下无人管理进程。
- PTY 只在必要交互任务上启用，定义输入、EOF、窗口大小、取消和秘密输入不回显；非交互命令继续普通 Shell，不为所有操作强加 PTY。
- 用户转向作为新控制事件进入会话，在安全边界修改目标/取消；停止当前工具或等待其完成的语义必须明确。
- 正常验收：长测试后台运行时用户可查看进度、取消并继续别的只读任务，结果归属不混乱。
- 故障：通知重复按事件 ID 去重；断开终端不丢任务所有权；后台进程占满配额不饿死前台取消。重启后按 P5 协调，不能自动复活写进程。

### P7.5 子 Agent（单 Agent 稳定后再做）

- 先支持只读 explore/review，再考虑 coder；子任务有明确输入、产物、父身份、共享总预算、子额度、深度和并发上限。
- 权限取父上限交集，子 Agent 不能批准自己。读上下文按需裁剪，结论必须带来源，主 Agent 独立核对再采用。
- 并行写使用显式 worktree；直接目录的冲突写保守串行。合并检查版本与冲突，不用最后写入者覆盖。
- 正常验收：主任务委派定位/审查后完成真实跨文件修复，统计额外调用是否值得；不用团队规模证明质量。
- 故障：子任务超预算、父任务取消、修改冲突均留下可解释状态与保留产物；子任务试图扩大网络/秘密权限被拒。
- 多角色团队、mailbox、复杂 DAG 只在已有任务证明收益时另立计划，不影响基础可用版本交付。

## 9. P8：交互、真实任务评测与发布门槛

### P8.1 可用的终端操作面

- 逐项提供状态、diff、测试、上下文、compact、权限、取消、会话列表/resume、doctor、资源清理；它们调用统一服务，不各自执行第二套 Runtime。context/compact 和 sessions 维护命令现已接入；未实现命令不出现在“已支持”列表。
- 展示当前目录、执行模式、模型、授权状态、费用/usage 是否未知、测试及独立验证结果；流式正文与审批不互相覆盖。无 TTY 时不阻塞提问，JSONL 具有稳定版本及退出码。
- 正常验收：首次安装用户无需读源码可配置、完成任务、审查和恢复；Ctrl-C、EOF、终端断开有清楚行为。
- 故障：渲染器写入失败不能启动额外工具；审批输入与普通转向不串线；错误中含秘密也不直接打印。

### P8.2 可复现任务与独立验收

- P3 起建立固定小回归集：只读定位、非 Git 创建项目、脏目录单文件修复、跨文件失败后纠错、长输出/压缩、拒绝/取消/超时、崩溃恢复。相关能力未实现时标未覆盖，不伪造通过。
- Harness 真正 checkout 指定 commit，固定环境/镜像/模型/参数/预算。评测隔离不改变产品默认直写行为；每个 trial 都在控制器创建的目录开始。
- 加入真实中小仓库：至少涵盖两种项目布局、跨文件依赖、测试失败日志及已有未提交修改。隐藏验证器不进入模型可读工作区；补丁含二进制/模式变更的覆盖范围明确。
- 逐条提供原始结果和失败分类；任务成功率仅统计独立 verdict，可评测失败与基础设施失败分列。固定模型的每个关键配置预先约定至少三次重复；样本太少不宣称统计优势。
- 初始发布目标：固定验收集全部报告，确定性正确性/权限/清理回归全通过；真实任务目标及预算在运行前冻结，未达标保留失败，禁止事后挑选成功案例或降低门槛。成功率具体阈值依据首轮基线和用途确定，不凭空编一个成熟率。
- 故障：空补丁/删除测试不蒙混通过；验证器超时/启动失败记不可评测或基础设施错误；仓库/模型版本漂移阻止混合比较。

### P8.3 安全、长任务与性能回归

- 提示注入、仓库不可信配置、符号链接、Shell、秘密、MCP、依赖脚本、容器挂载形成持续专项回归。越权零容忍只指受测强制边界，不作绝对安全宣传。
- 长任务覆盖多次压缩、重复工具失败、后台取消和恢复；测量峰值内存、Artifact 增长、首字延迟、工具等待、Token、调用数、总时间与清理结果。
- 每次优化对比固定任务与预算，不用单个 mock 延迟、演示数量或更大模型掩盖退步。真实模型置信度与确定性边界分开。
- 故障：大仓库遍历导致阻塞、日志持续增长、反复压缩不收敛都要有清晰停止和残留诊断；长任务不能依赖人工杀进程。

### P8.4 安装、升级与支持矩阵

- 干净环境安装 wheel、仓库外运行，同一安装版验证 Local/Rootless Docker；记录 Python、OS、daemon/存储驱动、镜像 ID、配置和数据库 Schema 版本。
- doctor 仅检查不改服务器公共配置；资源 prune 默认预览并核对归属，保留未交付修改。日志/会话保留和删除可解释；升级迁移前备份，失败不给出虚假成功。
- 正常验收：新用户按 README 完成配置到任务交付；项目外测试不依赖 editable 源码路径。
- 故障：迁移失败可恢复备份；磁盘满不能破坏旧状态；缺 rg/Git/Docker 等依赖展示实际缺失项。未验证 Windows/macOS 不声称支持。
